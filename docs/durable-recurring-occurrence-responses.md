# Shared responses to ordinary recurring invitations

[ADR 0179](adr/0179-durable-shared-recurring-occurrence-responses.md) is accepted. Its implementation combines the [pure effective-notice selector](recurring-response-source-selection.md) with retained source history, authorization, private shared state and durable synthetic delivery. The [validation record](scaffold-validation.md) distinguishes completed local checks from the pending exact-head hosted gate.

Enable `CalendarInvitationResponseOptions.recurringOccurrences` explicitly with `CalendarRecurringResponseOptions(enabled: true)`. The default is disabled; the example enables it. Only a genuinely new ordinary recurring master correlation can enroll. Existing or purged history stays unknown, and upgrade never invents history or merges legacy commands. Every host receiving subsequent notices for an enrolled history must maintain proof even when new enrollment is disabled; a missing response runtime fails the ingress transaction.

Use `recurringOccurrenceResponse(openedInvitationId, originalStart)` to read a selection. The opened entry may be the master, an exact single notice or a covering range notice. The original is the unmoved DATE/UTC/named-zone identity, not the replacement DTSTART. Selection uses an exact single notice, otherwise the latest covering range, otherwise the master. Active single/range/whole cancellation blocks new replies. The view separates the current controlling version from a recorded personal choice.

Send the returned evidence identity/revision/digest and original through `sendRecurringOccurrenceResponse`. Its nested command identifies the canonical master and membership source; its expected invitation revision fences that master. The opened entry is freshly read and authorized rather than independently client-revision-fenced. Both entry paths share `recurring-occurrence-v1` state under that master and original. Master responses and sibling originals remain independent. Retain the entire command, including its UUID, across uncertain retries; changing its route or proof requires a new explicit command. A new choice uses the current response revision and a strictly later actual database-second stamp.

Old single-instance read/activity APIs alias this shared state for enrolled histories, with scalar sends disabled. Range entries still reject through those legacy APIs. The new range entry path requires an explicit original and sends one occurrence REPLY without RANGE. Legacy non-enrolled and complete-bundle workflows keep their existing identities.

## Source proof and calendar independence

Trusted ingress atomically writes a selection head, immutable evidence version and indexed pins to every source in its deduplicated closure. Each version contains references and flat transition evidence, not copied source bodies or a native calendar snapshot. Exact packet bindings, digest, closure, pin equality, membership, recipient claims and cancellation/restoration transitions are revalidated under one shared work budget. Corruption or incomplete evidence cannot fall back to a master reply.

A range cancellation retains its pre-cancellation basis and masks all later originals, including moved exceptions. Only a newer same-anchor restore-only REQUEST matching the retained timing/content and strict version floors clears that mask. Another active cutoff remains effective. Repeated cycles retain bounded flat proof. Whole-series cancellation blocks replies; a newer master alone cannot erase a separate cutoff.

Receipt, dismissal, Add to calendar and Apply do not record participation. Source-only restoration can enable a reply without calendar adoption or Apply. Shared native drafts never provide source proof. A changed proof withdraws unsent intents on older evidence, even when the controlling component is unchanged; recorded choices remain historical and never reactivate automatically.

## Storage, authority and retention

Three private tables hold the head, evidence and indexed source pins. The existing response delivery has one nullable evidence reference. No response-state schema changes are needed. For this profile only, the state's source digest records the selection digest, allowing the personal revision and historical choice to survive delivery pruning. Delivery source identity/digest still identify the membership packet. The retained receipt stores the actual opened entry, while the base command/state/delivery parent identify the canonical master; together with evidence this reproduces the exact route-bound command hash. Legacy receipt/hash meanings are unchanged.

Defaults are 128 heads per recipient/4,096 per scope, 64 versions per head, 64 flat history/notice slots, 16,384 pins per recipient/262,144 per scope, and 4 MiB evidence JSON per head/16 MiB per recipient/64 MiB per scope. Each version has at most 65 source packets, 262,144 raw bytes, 1,000 components, 32 VTIMEZONE components and 200,000 shared recurrence-work units. Existing raw-source and response quotas still apply, including the aggregate 32 retained responses per canonical invitation. Capacity exhaustion rejects atomically without eviction or partial eligibility.

Host policy checks ordinary response operations plus independent recurring read/send/dispatch and evidence-maintenance operations. Context carries immutable current/proposed proof and the actual opened/master objects separately from the minimal REPLY. Every required source needs raw-read authority. Workers use no fabricated actor and recheck proof/current source vector, route, recipient access, generation, expiry and database lease before submitting stable payloads. External fresh-check policies retain their documented after-check revocation race.

Current and delivery-pinned proof protects all referenced sources. Retired unreferenced evidence uses the configured terminal retention (30 days by default). After all entries become inactive and external references permit cleanup, payload and pins are scrubbed in order; a minimal unknown-history marker prevents reenrollment while references survive. It is eventually removed with eligible entries, without a self-pin deadlock. Personal state follows its existing entry-pruning boundary. A purged or unavailable selection cannot authorize a new response.

The example offers the same private choice from master selection and an instance notice, displays the effective version, and freezes uncertain commands. Transport remains synthetic MIME recording. Real email/provider trust, suffix participation, legacy adoption and external-client compatibility remain separate work.
