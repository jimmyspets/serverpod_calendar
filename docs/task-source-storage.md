# Source-preserving task storage

[ADR 0098](adr/0098-task-source-storage-model.md) implements the storage prerequisite for the [confirmed create-only task import contract](task-import.md). Concrete representation and service mechanics remain under draft review. **There is no authenticated task import/export endpoint in this batch.**

The maintainer selected read-only preservation of rich source metadata now, with native participant/attachment/alarm editors later. Current source state is server-only, available to trusted policy through immutable current/final proposed context. Ordinary task responses and generated clients gain no rich-source disclosure group. Source participants remain separate from native assignments; source alarms/acknowledgements/snoozes remain unarmed and unverified. Storage never fetches a URI, generates firing instants, assigns a person or invents history.

## Stored values

The active task row now has nullable `sourceState` and a separate nullable private `importBaseline`. Each source state retains a complete decoded master and bounded raw progress components: native content/progress, independent protocol version, exact original identity, text annotations and structured metadata. Metadata retains grouped categories/comments/contact, source organizer/attendee claims, unresolved relationships, inert URI attachments and the supported DISPLAY/snooze profile. Signed alarm durations preserve sign and units. Lists/maps are detached and frozen by validation, including nested participant parameter lists and recurrence selections.

Current source copies must agree with native master/per-original query projections or the service fails unavailable. Explicit sparse progress components have their own row even with absent progress fields; originals without a row inherit the entire master progress. Import creates no history. The storage-only database fixtures exercise this representation directly and are not an import implementation.

Source conversion preserves supported decoded property presence, optional values, grouping, ordering and timing forms. Equivalent wire spellings and redundant default VALUE syntax are not a file archive. Future export regenerates VCALENDAR presentation and pinned VTIMEZONE data. Current validation rebuilds that supported profile and checks decoded equality, including full-horizon named-zone validation. Unsupported or lossy state rejects rather than being flattened or dropped.

## Native changes

Ordinary content edits preserve annotations/source metadata. Explicit repeated occurrence text/priority follows the master; only actually changed component versions advance. Explicit timing that no longer matches the master projection, missing alarm anchors, orphaned originals and unsupported/over-budget state reject atomically. Metadata remains source-only in this increment; native editors require future explicit permissions/disclosure and commands.

Assignment-only edits leave SEQUENCE and protocol timestamps unchanged, as confirmed by the maintainer. Native revision, audit time and scope generation still advance. Occurrence progress actions now change only their component's version, leaving the master version unchanged; whole-task API revision/scope generation still advance. New local components start at SEQUENCE 0 with known creation time. Legacy occurrence rows initialize a local sequence-zero baseline on their next actual change, then advance to 1, omitting unknown CREATED. No import baseline is invented. Unchanged commands retain versions and create no progress row/history solely to pin an inherited default.

Existing source versions and omissions survive initial conversion. Native changes use nondecreasing whole-second timestamps and reject sequence overflow. Imported non-recurring tasks must retain unknown prior progress even when current fields are neutral; conversion remains blocked until future explicit adoption/reconciliation. Native-created clean tasks retain their existing conversion behavior.

## Private baseline and limits

The baseline contains a versioned canonical decoded last-source snapshot plus source sequence, pinned to the IANA data profile. It is separate from current state and is retained unchanged through local edits, so it may contain removed source values. It excludes native UUID/revision, audit time, assignments and regenerated envelope decorations. Never include it in ordinary views, policy snapshots, receipts, cursors, logs or current-state export. Deletion scrubs baseline, source metadata, occurrence state and history with the active data, leaving only the existing minimal identity marker.

The baseline cap is 2 MiB UTF-8. Unknown profiles, wrong UIDs, invalid/noncanonical snapshots and inconsistent source sequence fail validation. Source-bearing edits remain within existing wire component/text/alarm/recurrence budgets, including 64 overrides per series and the file-wide raw component cap. Source-free native tasks retain their existing 1,000 recorded-original limit. No partial mutation or silent metadata removal occurs at a cap.
