# RFC 9110 — HTTP semantics

Source: [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), notably sections 8–9, 13 and 15. **Implemented today: No, for every row.** [Status legend](README.md). This is an inventory of application-relevant feed features, not every HTTP server feature. The HTTP stack remains a selected platform dependency.

| Header, method or feature | Purpose | First-release plan | Notes |
| --- | --- | --- | --- |
| GET | Download feed | Yes — planned | Valid secret URL and current publication authority |
| HEAD | Headers without body | Yes — planned | Equivalent status/representation metadata |
| ETag | Representation validator | Yes — planned | Stable for unchanged representation |
| Strong validator generation | Exact representation identity | Yes — planned | Hash-byte strategy; handle content encodings separately |
| If-None-Match | Conditional retrieval | Yes — planned | Lists, wildcard and weak comparison |
| 304 Not Modified | Unchanged result | Yes — planned | No body; authorization/revocation checked first |
| 200 OK | Successful retrieval | Yes — planned | Current content and validator |
| 404 Not Found | Opaque credential denial | Yes — planned | Generic invalid/revoked-token response under ADR 0004 |
| Content-Type | Media format | Yes — planned | text/calendar with approved charset |
| Content-Length | Representation size | Host/library | Correct GET/HEAD and bodyless status semantics |
| Content-Encoding | Encoded variant | Host/library | Exact enabled encodings undecided; validators must remain correct |
| Vary | Variant selection | Yes — planned | Needed for negotiated representations if enabled |
| Date | Response time | Host/library | Does not alter calendar metadata or ETag |
| Last-Modified | Time validator | No — deferred | ETag-only initial HTTP profile; ICS LAST-MODIFIED remains independent |
| If-Modified-Since | Date revalidation | No — deferred | No initial HTTP modification-date contract; ETag/If-None-Match governs revalidation |
| If-Unmodified-Since | Date precondition | No — deferred | No initial HTTP modification-date contract; apply RFC unavailable-date handling |
| If-Match | Revision precondition | Yes — planned | Feed adapter evaluates GET/HEAD strong-comparison preconditions and 412 after authorization, with RFC precedence; native revisions remain separate |
| Range | Partial retrieval | No — deferred | Ignore range selection; use normal complete ICS/conditional response flow |
| If-Range | Range validator | No — deferred | Ignore with unsupported ranges; no partial-download contract |
| Content-Range / 206 | Partial content | No — deferred | No partial feed responses; ordinary GET/HEAD/304 semantics retained |
| Accept negotiation | Select representation | No — outside contract | Fixed text/calendar representation regardless of media preferences; no JSON/XML format negotiation |
| Content-Language | Content language | Yes — planned | Optional host-configured intended-audience language tags; omit when unspecified, no inference or Accept-Language negotiation |
| Authorization | Header credential | Host/library | Host/native API integration; feed uses opaque URL capability |
| Redirects / Location | New resource address | No — deferred | No automatic replacement/login/origin redirects; revoked credentials fail without exposing a replacement URL |
| OPTIONS / Allow | Method discovery | Host/library | Final route/method policy required |
| POST/PUT/DELETE on feed | Feed mutation | No — outside contract | Feed URL grants read-only access; management uses host APIs |
| CONNECT/TRACE service | Proxy/debug surface | No — outside contract | Not module features |
| Other error mapping | Failure responses | Yes — planned | Privacy-safe 400/405/429/503/500 mapping under ADR 0016; opaque credential 404 and failed If-Match 412 retained; 429 is defined by RFC 6585 |

Native Serverpod endpoint transport is not automatically the same interface as the subscription route. Caching policy is listed in [RFC 9111](rfc-9111.md). The module must not return content or 304 from a revoked token, regardless of cached representation. See [ADR 0004](../adr/0004-subscription-feeds.md), FR-12/FR-13 and [HTTP/feed evidence](../roadmap.md#feeds).

## Decision records

The selected HTTP contract follows [ADR 0016](../adr/0016-subscription-http-profile.md), with the baseline promotion recorded in [RFC scope](README.md). Preserve ETag precondition order, opaque denial, privacy-safe errors and bodyless HEAD/304. Host/library details require configuration and tests.
