# RFC 7986 — Calendar property extensions

Source: [RFC 7986](https://www.rfc-editor.org/rfc/rfc7986.html), sections 4–6. **Wire/interoperability implementation: No, for every row.** Scoped native decoded NAME/DESCRIPTION/COLOR editing/storage is now implemented under [ADR 0050](../adr/0050-calendar-presentation-and-protocol-text.md); Native URL/categories/image/refresh metadata and authorized category search are also implemented under [ADR 0051](../adr/0051-calendar-links-categories-images-refresh.md). These slices are not an ICS parser/serializer or feed output. [Status legend](README.md). Calendar descriptions are first-release scope; UID, LAST-MODIFIED and COLOR join the planned baseline; all listed rows now have a selected first-release profile; detailed contexts/limits and implementation remain pending.

| Property or parameter | Purpose | First-release plan | Notes |
| --- | --- | --- | --- |
| NAME | Calendar name | Yes — planned | Preserve optional legal language variants; native displayName is separate under [ADR 0047](../adr/0047-calendar-names-identifiers-and-deletion-storage.md), not a mandatory wire NAME or implicit rename/publication fallback. Scoped native language/text editing and disclosure under ADR 0050; ALTREP/extension parameters, parsing and publication remain pending |
| DESCRIPTION | Calendar description | Yes — planned | Calendar-level context, separate from event descriptions and native UI description; scoped decoded language variants under ADR 0050, wire support pending |
| UID | Calendar identity | Yes — planned | Native separate generated stable calendar UID under ADR 0052, distinct from API UUID; source/aggregate-feed identities and wire output remain pending, never a bearer token |
| LAST-MODIFIED | Calendar update | Yes — planned | Native read-only UTC whole-second calendar revision time under ADR 0052; full object/selection/publication change tracking, wire output and ETags pending |
| URL | Alternative representation | Yes — planned | Scoped native HTTP/HTTPS editing/storage under ADR 0051; host reference validation, no fetch; wire/feed support pending |
| CATEGORIES | Calendar labels | Yes — planned | Scoped native exact text/language search with per-object category disclosure under ADR 0051; no ownership/permissions; wire grouping pending |
| REFRESH-INTERVAL | Polling hint | Yes — planned | Scoped native positive unit-preserving hint capped at 365-day equivalent under ADR 0051; no polling or refresh guarantee; wire/feed support pending |
| SOURCE | Refresh source | Yes — planned | Preserve imported URI privately for authorized interchange/edit retention; no native editing, subscription output or automatic fetching |
| COLOR | Display color | Yes — planned | Scoped native protocol editing accepts RFC CSS3 names, separate from native RGB under ADR 0050; serialization/publication/client rendering pending |
| IMAGE | Calendar image | Yes — planned | Scoped native URI image metadata under ADR 0051; HTTP/HTTPS only, no binary/fetch/resize or remote-image loading; wire/feed support pending |
| CONFERENCE | Conference access | Yes — planned | Native/interchange event/task access-link metadata; meeting creation/joining/providers stay host-owned; no VTODO scheduling mail |
| DISPLAY parameter | Image presentation | Yes — planned | Scoped native multi-token/omitted DISPLAY preservation under ADR 0051; default BADGE, unknown hints suppress helper rendering; no image loading or wire support |
| EMAIL parameter | Contact email | Yes — planned | Native/interchange organizer/attendee metadata with host validation/disclosure; no identity proof or automatic routing authority |
| FEATURE parameter | Conference capabilities | Yes — planned | Native/interchange standard conference tags; host disclosure keeps moderator-only links/codes from attendees |
| LABEL parameter | Display label | Yes — planned | Native/interchange conference labels; other relationship contexts remain separate |
| Calendar property cardinalities | Metadata validity | Yes — planned | Apply accepted contexts; do not assume single-language-only semantics |

General metadata support does not require all feed clients to render every field. Aggregate feeds have their own name/identity and description; multiple URLs for one feed share metadata. Module/interchange support remains independent of the narrower feed profile. All listed fields have selected scope; exact legal contexts, value constraints and projections need specification before accepting input. See [ADR 0014](../adr/0014-rfc-extension-decisions.md), FR-24 and [metadata work](../roadmap.md#icalendar-and-metadata).

## Decision records

Selected descriptive metadata follows ADRs [RFC scope](README.md) and [0014](../adr/0014-rfc-extension-decisions.md). Calendar images remain URI-only; imported SOURCE is private and excluded from subscriptions. Detailed constraints and per-surface projections still need implementation review.
