# RFC 7986 — Calendar property extensions

Source: [RFC 7986](https://www.rfc-editor.org/rfc/rfc7986.html), sections 4–6. **Implemented today: No, for every row.** [Status legend](README.md). Calendar descriptions are first-release scope; UID, LAST-MODIFIED and COLOR join the planned baseline; all listed rows now have a selected first-release profile; detailed contexts/limits and implementation remain pending.

| Property or parameter | Purpose | First-release plan | Notes |
| --- | --- | --- | --- |
| NAME | Calendar name | Yes — planned | Planned metadata baseline; language/multiplicity constraints open |
| DESCRIPTION | Calendar description | Yes — planned | Calendar-level context, separate from event descriptions |
| UID | Calendar identity | Yes — planned | Stable logical calendar/feed identity; never a bearer token |
| LAST-MODIFIED | Calendar update | Yes — planned | Persistent metadata, relevant to output/ETag |
| URL | Alternative representation | Yes — planned | Editable native/interchange calendar/feed metadata; no fetch or exposure of another URL credential |
| CATEGORIES | Calendar labels | Yes — planned | Searchable free-form labels with host validation; separate from event labels and permissions |
| REFRESH-INTERVAL | Polling hint | Yes — planned | Host-configurable positive minimum interval hint in native/interchange/feed metadata; no refresh guarantee |
| SOURCE | Refresh source | Yes — planned | Preserve imported URI privately for authorized interchange/edit retention; no native editing, subscription output or automatic fetching |
| COLOR | Display color | Yes — planned | Optional metadata baseline; rendering is client-dependent |
| IMAGE | Calendar image | Yes — planned | Native/interchange calendar image links only; host-managed files, no binary/fetch/resize/storage; disclosure controlled by host |
| CONFERENCE | Conference access | Yes — planned | Native/interchange event/task access-link metadata; meeting creation/joining/providers stay host-owned; no VTODO scheduling mail |
| DISPLAY parameter | Image presentation | Yes — planned | Native/interchange BADGE/GRAPHIC/FULLSIZE/THUMBNAIL hints on calendar IMAGE; host controls rendering, distinct from alarm action |
| EMAIL parameter | Contact email | Yes — planned | Native/interchange organizer/attendee metadata with host validation/disclosure; no identity proof or automatic routing authority |
| FEATURE parameter | Conference capabilities | Yes — planned | Native/interchange standard conference tags; host disclosure keeps moderator-only links/codes from attendees |
| LABEL parameter | Display label | Yes — planned | Native/interchange conference labels; other relationship contexts remain separate |
| Calendar property cardinalities | Metadata validity | Yes — planned | Apply accepted contexts; do not assume single-language-only semantics |

General metadata support does not require all feed clients to render every field. Aggregate feeds have their own name/identity and description; multiple URLs for one feed share metadata. Module/interchange support remains independent of the narrower feed profile. All listed fields have selected scope; exact legal contexts, value constraints and projections need specification before accepting input. See [ADR 0014](../adr/0014-rfc-extension-decisions.md), FR-24 and [metadata work](../roadmap.md#icalendar-and-metadata).

## Decision records

Selected descriptive metadata follows ADRs [RFC scope](README.md) and [0014](../adr/0014-rfc-extension-decisions.md). Calendar images remain URI-only; imported SOURCE is private and excluded from subscriptions. Detailed constraints and per-surface projections still need implementation review.
