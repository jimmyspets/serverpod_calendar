# RFC 9074 — VALARM extensions

Source: [RFC 9074](https://www.rfc-editor.org/rfc/rfc9074.html), sections 3–8. **Implemented today: scoped pure VTODO DISPLAY syntax and optional UID/ACKNOWLEDGED source preservation under [ADR 0094](../adr/0094-vtodo-display-alarm-source-profile.md); bounded task sibling snooze source links now extend this under [ADR 0095](../adr/0095-vtodo-snooze-source-profile.md); VEVENT source preservation now follows under [ADR 0110](../adr/0110-unarmed-event-source-alarms.md); native actions/runtime and remaining extensions are unimplemented.** [Status legend](README.md). First-release alarm execution and reusable notification integration are required; [ADR 0020](../adr/0020-notification-delivery-scope.md) uses a connected streaming example and excludes direct platform push implementations. The selected personal alarm/interchange baseline below is planned under [ADR 0009](../adr/0009-alarms-and-notification-boundaries.md); this is not blanket RFC support.

Native Flutter reminder actions and connected streaming notifications are independent of external feed alarm rendering. Keep personal acknowledgement/snooze state private, calendar timing/state in the calendar module, generic notification delivery outside it and platform providers in external adapters, and OS presentation in Flutter. Trigger/date-only/expiry/retry policies must be approved and tested. See FR-28–FR-31 and [alarm work](../roadmap.md#alarms-and-push), [push delivery work](../roadmap.md#alarms-and-push), [connected-client integration work](../roadmap.md#alarms-and-push).


Scope update on 2026-10-19: the maintainer approved every previously Proposed row as Yes — planned; see [RFC scope](README.md). Detailed constraints and validation remain implementation work; other status categories retain their existing scope. No runtime implementation is claimed.

## Pure task source state boundary

[ADR 0094](../adr/0094-vtodo-display-alarm-source-profile.md) implements only unarmed task DISPLAY wire definitions with optional source UID/ACKNOWLEDGED, bounded trigger/repeat data and matching occurrence inheritance. Source acknowledgement is not an authorized native action; no recipient, firing instant, suppression or delivery is inferred. Snooze relationships/RELATED-TO still reject until their own profile. Event alarms and all native privacy/action/runtime/notification work remain required. No broad RFC 9074 or connected-client evidence follows.

## Bounded task sibling snooze source links

[ADR 0095](../adr/0095-vtodo-snooze-source-profile.md) adds same-raw-VTODO SNOOZE relations to acknowledged original siblings, requiring own UID and absolute UTC trigger without repeats/chains/detached links. Source acknowledgement remains unverified data and no native action, recipient, consent, firing instant or delivery is inferred. Target UID text shares existing budgets; occurrence lists inherit or match completely. This supersedes prior snooze-wire rejection only for this structural profile, with native privacy/activation/actions/runtime and event support still pending.


## Event source preservation

[ADR 0110](../adr/0110-unarmed-event-source-alarms.md) now implements the same bounded unarmed DISPLAY/UID/ACKNOWLEDGED/sibling-SNOOZE source profile for VEVENT through storage/import/export/replacement. See [limits and privacy](../event-source-alarms.md). This supersedes earlier event-support-pending wording only for this source slice. Source acknowledgement and snooze links remain unverified claims, separate from native recipient-level actions, consent, delivery and private state. The planned table rows above continue to require native/runtime work.
