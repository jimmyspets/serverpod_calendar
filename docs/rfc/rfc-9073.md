# RFC 9073 — Event publishing extensions

Source: [RFC 9073](https://www.rfc-editor.org/rfc/rfc9073.html), sections 4–7. **Implemented today: No, for every row.** [Status legend](README.md). Structured PARTICIPANT/VLOCATION/VRESOURCE are selected for native event/task APIs and interchange; all listed rows now have selected first-release scope; exact per-component allowlists, numeric limits and implementation remain pending.

| Component, property or parameter | Purpose | First-release plan | Notes |
| --- | --- | --- | --- |
| PARTICIPANT | Structured participant | Yes — planned | Native/interchange event/task metadata with host validation/disclosure; no directory creation, ATTENDEE replacement or automatic invitations |
| VLOCATION | Structured location | Yes — planned | Native/interchange event/task location metadata; host owns room identities/maps/lookup; no implicit reservation |
| VRESOURCE | Structured resource | Yes — planned | Native/interchange event/task resource metadata with host-validated links; no directory creation or implicit booking |
| LOCATION-TYPE | Location category | Yes — planned | Native/interchange standardized RFC-referenced vocabulary with host validation; no host-kind replacement or booking changes |
| PARTICIPANT-TYPE | Participant category | Yes — planned | All RFC standard categories with host validation/disclosure; required once per PARTICIPANT; no permission, attendee-role or assignment effects |
| RESOURCE-TYPE | Resource category | Yes — planned | Native/interchange ROOM/PROJECTOR/REMOTE-CONFERENCE-AUDIO/REMOTE-CONFERENCE-VIDEO with host validation; extra registered values need explicit approval |
| CALENDAR-ADDRESS | Scheduling address | Yes — planned | Native/interchange PARTICIPANT metadata with host-validated mappings; ATTENDEE matching does not prove identity or authorize invitations/scheduling |
| STYLED-DESCRIPTION | Rich description | Yes — planned | Native/interchange event/task URI links only with ordinary plain-text DESCRIPTION retained; no inline HTML, fetching or rendering |
| STRUCTURED-DATA | Associated data | Yes — planned | Native/interchange URI references only in event/task and approved structured contexts; no inline text/binary, fetching or directory import; schema/media metadata selected below; exact constraints pending |
| ORDER parameter | Display ordering | Yes — planned | Native/interchange positive presentation order in legal repeatable-property contexts; deterministic ties, no booking/scheduling priority |
| SCHEMA parameter | Data schema | Yes — planned | Native/interchange schema URI and declared FMTTYPE on structured-data links; no fetching, remote-document validation or interpretation |
| DERIVED parameter | Derived metadata flag | Yes — planned | Preserve/export marker; DERIVED=TRUE read-only to ordinary native clients; trusted host source updates, no automatic derivation engine |
| Nested components | Rich publication structure | Yes — planned | Bounded event/task children and participant location/resource children; no arbitrary recursion; participant location disclosure requires permission |
| Shared core properties | Identity/text/location fields | Yes — planned | Reuse selected field policies only in legal per-component contexts; stable UID, CONTACT import-only, URI-only content and host disclosure |

Evaluate all rows against full module needs separately from subset feed rendering. Rich metadata must not expose private participants/locations, create directory entries, grant access, reserve a resource or trigger remote requests. An unsupported component is rejected until its handling is specified. See [ADR 0014](../adr/0014-rfc-extension-decisions.md) and [profile contracts](../roadmap.md#design-contracts).

## Decision records

Selected structured metadata follows [ADR 0014](../adr/0014-rfc-extension-decisions.md): bounded legal nesting, URI-only content, legal shared fields and participant-controlled location disclosure enforced by host policy. Exact per-component schemas and limits remain implementation work.
