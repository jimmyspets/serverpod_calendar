# RFC 9111 — HTTP caching

Source: [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html), notably sections 3–5. **Scoped origin implementation:** the optional event-feed profile under [ADR 0116](../adr/0116-optional-event-subscription-contract.md) now implements the declared origin behavior; full local batch validation passed. Host/cache/client infrastructure remains separately validated. [Status legend](README.md). These are relevant origin/integration requirements; the module is not building a general shared cache.

Private caching does not identify subscribers and cannot erase data already downloaded. Host/library integration does not imply this project controls third-party client caches. The selected policy in [ADR 0016](../adr/0016-subscription-http-profile.md) is Cache-Control: private, no-cache, max-age=0, must-revalidate for successful responses, including appropriate 304 metadata, and no-store for all errors/denials. Omit proxy-revalidate and Expires initially. Verify header semantics and host integration; directives do not guarantee instant synchronization. See [ADR 0004](../adr/0004-subscription-feeds.md), NFR-04/NFR-08 and [RFC 9110](rfc-9110.md).

## Decision records

The selected response-specific caching contract follows [ADR 0016](../adr/0016-subscription-http-profile.md); the earlier baseline promotion is recorded in [RFC scope](README.md). Host/client behavior still needs integration evidence.

## Optional origin profile, 2026-10-25

The [feed guide](../http-event-feeds.md) describes the implemented fixed ICS/identity-encoding profile, authorization before content/304, exact-byte strong ETags, conditional precedence, bodyless HEAD/304 and no-store errors. No representation cache, HTTP date validators, ranges, shared-cache reuse or redirects are added. Origin tests do not establish arbitrary proxy/cache configuration or external-client behavior. Full local batch validation passed.
