# RFC 6047 — iMIP email binding

Source: [RFC 6047](https://www.rfc-editor.org/rfc/rfc6047.html), sections 2–5. **Implemented today: No, for every row.** [Status legend](README.md). This RFC binds scheduling to email; it does not add a separate event property model.

RFC 5322 and MIME syntax/transport dependencies are delegated to evaluated libraries/providers, not independently claimed as complete module implementations. The host/library rows are required integration behavior where the accepted payload uses them, not evidence of working dependencies today.

Project additions: transactionally persist scheduling mutations and outbound intent, deduplicate inbound processing, retry visibly and bound recipients/input. These are application contracts, not RFC properties. Tasks are supported natively; VTODO email scheduling is deferred under [ADR 0011](../adr/0011-defer-vtodo-scheduling.md); unsupported task scheduling must not mutate tasks, send automatic replies or enter the outbound delivery queue. See [ADR 0007](../adr/0007-scheduling-and-email.md), FR-22/FR-23 and [mail integration work](../roadmap.md#scheduling).

Maintainer decision on 2026-10-19: component hints are planned; S/MIME signatures and encryption are deferred. The selected email capability is a restricted iMIP-compatible profile without complete RFC 6047 conformance. Trusted host-verified scheduling authority remains mandatory, with untrusted/unsupported traffic rejected or quarantined without mutation or automatic replies. See [ADR 0015](../adr/0015-restricted-imip-profile.md).
