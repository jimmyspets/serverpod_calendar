# RFC 6047 — iMIP email binding

Source: [RFC 6047](https://www.rfc-editor.org/rfc/rfc6047.html), sections 2–5. **Implemented today: scoped decoded-part semantic checks under ADR 0142; single-part example outbound composition is implemented under ADR 0143; bounded raw single/flat extraction is implemented under ADR 0144; verified native/provider integration and complete MIME/transport remain unimplemented.** [Status legend](README.md). This RFC binds scheduling to email; it does not add a separate event property model.

RFC 5322 and MIME syntax/transport dependencies are delegated to evaluated libraries/providers, not independently claimed as complete module implementations. The host/library rows are required integration behavior where the accepted payload uses them, not evidence of working dependencies today.

Project additions: transactionally persist scheduling mutations and outbound intent, deduplicate inbound processing, retry visibly and bound recipients/input. These are application contracts, not RFC properties. Tasks are supported natively; VTODO email scheduling is deferred under [ADR 0011](../adr/0011-defer-vtodo-scheduling.md); unsupported task scheduling must not mutate tasks, send automatic replies or enter the outbound delivery queue. See [ADR 0007](../adr/0007-scheduling-and-email.md), FR-22/FR-23 and [mail integration work](../roadmap.md#scheduling).

Maintainer decision on 2026-10-19: component hints are planned; S/MIME signatures and encryption are deferred. The selected email capability is a restricted iMIP-compatible profile without complete RFC 6047 conformance. Trusted host-verified scheduling authority remains mandatory, with untrusted/unsupported traffic rejected or quarantined without mutation or automatic replies. See [ADR 0015](../adr/0015-restricted-imip-profile.md).


## Scoped decoded-part prerequisite

Accepted [ADR 0142](../adr/0142-pure-decoded-imip-calendar-parts.md) implements a pure already-transfer-decoded iMIP calendar-part gate for existing event/free-busy scheduling payloads. It validates MIME method/component/charset, bounded mailto addresses, protection and resource limits without sender authority or side effects. See [the API/profile guide](../imip-calendar-parts.md). Whole-email MIME/provider integration, native reconciliation, transport and external evidence remain separate required work; complete RFC 6047 conformance is not claimed.

Calendar-address syntax has a bounded pure subset; host-verified routing/authority remains planned. Complete message/part selection, multipart, headers, transfer decoding/encoding, trusted origin, durable routing and actual delivery remain host/library integration work. No complete MIME/RFC 6047 row is established by accepting one decoded part.


## Scoped synthetic outbound composition

Accepted [ADR 0143](../adr/0143-synthetic-host-outbound-imip-composition.md) implements example-host-only enough_mail composition for existing authorized REQUEST/CANCEL synthetic deliveries. It preserves exact calendar bytes, uses bounded deterministic UTF-8/base64 MIME and adds a local fixture field. See [the guide](../outbound-imip-composition.md). No network delivery, inbound parser, schema or complete RFC 6047 conformance follows; reusable modules remain MIME-provider independent.


## Scoped raw extraction

Accepted [ADR 0144](../adr/0144-bounded-host-raw-imip-mime.md) implements host-only bounded raw MIME extraction over the existing library: single/flat alternative shapes, critical-header/parameter guards, selected transfer decoding, protection checks and fixed budgets. See [the profile/API guide](../raw-imip-extraction.md). It returns untrusted calendar data only; verified provider ingress/native dispatch, broader MIME/transport and external evidence remain separate. No schema, endpoint, identity inference or real sending is added.
