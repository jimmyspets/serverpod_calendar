# Master lifecycle after source range restoration

Accepted [ADR 0166](adr/0166-master-lifecycle-after-source-range-restoration.md) extends the explicit master applyCancellation/applyUpdate workflow after [restoration](source-range-restoration.md) and [master composition](restoration-master-composition.md). Receiving or reviewing messages changes no event and sends no response.

Whole-series CANCEL suppresses the master while preserving the cleared range cutoff, canonical timing/content exceptions and individual cancellations. Later explicit active REQUEST reopening restores retained current values; it never reinstates the historical suffix cutoff or reopens individual cancellations. The entire linked native series must still match its verified accepted state. Local edits conflict rather than being overwritten.

A new CANCEL must supply SEQUENCE greater than the current master, every accepted component (including before the former cutoff), and both historical cancellation/restoration source versions. Missing retained sequences compare as zero without rewriting source omissions. A later timestamp does not waive the floor. This conservative application policy is stricter than a universal RFC rule. Reopening follows existing master sequence/timestamp ordering; an equal sequence with a later DTSTAMP can qualify. Source timestamps/omissions remain exact and independent of database audit time.

Existing checkpoint JSON v9 binds the actual current master kind, baseline, composed native state and historical restoration receipt in distinct lifecycle digest namespaces. One frozen v7 acceptance/baseline/nullable-master descriptor is retained unchanged; there is no nested v8/v9 history or extra content snapshot. Direct v7-to-v9 and v8-to-v9 transitions are supported. Continued active writes after lifecycle remain v9. Strict legacy/v7/v8 readers remain; marker-only upgrades, contradictory kind/status, missing proof or corrupt bindings fail unavailable without fallback or read-time upgrades.

Independent action, native lifecycle, full source/link/read and accepted-occurrence/cancellation/restoration composition authority remain mandatory, including preliminary/final checks and fresh authorization of retained source identities after queue pruning. Protected previews check eligibility without mutation. Existing APIs, Flutter controls and history flags are reused; a history flag does not imply an active native cutoff.

Native/master/checkpoint writes, revisions, selected notice dismissal and scope/feed/alarm invalidation commit atomically. Calendar metadata time, personal definitions/actions and accepted-reminder deduplication remain independent. Exact latest-master and original-restoration retries reauthorize and return their original results without touching newer drafts, notices or generations. Earlier master commands retain existing supersession rules.

Existing complete-state byte/work/slot limits and private deletion scrubbing apply. No SQL, generated model/endpoint, dependency or cap expansion is added. New occurrence/range applications and repeated source cutoff transitions remain guarded pending separate review. Real mail and external-client certification remain separate. See [actual validation](scaffold-validation.md).
