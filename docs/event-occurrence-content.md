# Selected event occurrence content

Status: scoped implementation under [ADR 0106](adr/0106-single-event-content-overrides.md), following the confirmed selected-field, anchor-local and timing-inheritance choices. Concrete mechanics remain under draft review; validation is recorded separately in [the validation record](scaffold-validation.md).

`calendarEvent.changeOccurrenceContent` takes an immutable request with event UUID, expected revision, exact original start and one to three unique summary/description/location changes. Set supplies nonempty text; clear supplies no value and stores explicit empty text; follow-series removes the own value. Unselected fields remain unchanged. Existing text limits apply. Setting retains effective LANGUAGE/ALTREP annotations; clear/inherit removes own annotations. Text and links cause no network access.

An exception requires recurrence (including explicit additions), preserves original identity and changes only that original. Content on a THISANDFUTURE timing anchor never propagates. Content-only exceptions follow series timing, including later range changes. They participate in original membership and orphan checks but do not change occupied time or cancellation. Clearing timing preserves content. Moving a content-only single to a future timing anchor and back retains its component creation/version history. Explicit single timing and future timing still cannot collide.

The host receives the actual calendar/event, immutable `eventOccurrenceContentChange`, current overrides and final validated proposed overrides/protocol state. Require `updateEvent`; lifecycle permission remains independent. All writes use the durable scope transaction, expected revision and declared final authorization checks. Accepted native writes advance API revision/scope generation. Actual component changes advance only that component's protocol version; identical normalized saves keep protocol state stable. Master text edits leave explicitly pinned occurrence text and annotations intact.

Previews default to timing only. Optional `fieldGroups` may request summary, description and location. Both read and preview permissions must disclose every requested group; `disclosedGroups` identifies the response projection. Effective content and own override fields are independently filtered. Detail timing payloads and component-version lists omit content-only nodes whose fields are entirely withheld, preventing hidden content-exception presence from leaking through those lists. Free/busy never uses detail disclosure as its source.

VEVENT import preserves explicit occurrence text and legal annotations, including repeated master values and empty TEXT. Omission inherits. Explicit DTSTART still supplies standalone occurrence timing; cancellation/status/transparency remain within their existing bounded profile. Export preserves representable own fields and versions. **A native content-only exception without explicit replacement timing rejects the entire export**, because inventing DTSTART would pin timing and change later behavior. Native edits never silently add timing to make a file exportable.

The private event baseline is now `event-source-v2/<pinned-zone-version>`. Earlier imported v1 baselines reject as unavailable rather than being silently reinterpreted. This is an authorized pre-beta semantic break: explicitly recreate/reimport synthetic development data into a fresh database or another destination calendar as appropriate. No automatic reset, overwrite, adoption or source history is performed. Source-free native timing state remains compatible. No table column changes or new migration are needed; the new immutable DTOs live in existing JSON storage.

The example exposes selected field actions on saved occurrence previews when all three content groups are disclosed. Per-occurrence status/transparency, future content/cancellation, availability opening content exceptions, scheduling, alarm runtime and external-client compatibility are not added by this batch.
