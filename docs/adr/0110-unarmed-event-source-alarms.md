# ADR 0110: Unarmed event source DISPLAY alarms

Status: **confirmed reuse of the unarmed task profile, including bounded sibling snoozes; concrete mechanics under draft review**. Date: 2026-10-24.

Preserve VEVENT DISPLAY alarm definitions as read-only unarmed source data through wire/storage/import/export/replacement. Import creates no runtime alarm, recipient, notification intent, acknowledgement action, snooze action or delivery. Source alarm UID and ACKNOWLEDGED are unverified claims, separate from future native identities/state. Other actions, native controls, adoption/arming and execution remain separate.

Reuse the task parser for signed relative START/END or absolute UTC triggers, description/annotations, paired REPEAT/positive DURATION, optional UID/ACKNOWLEDGED and bounded same-component SNOOZE links. A snooze needs its own UID, absolute UTC trigger and an acknowledged original sibling; reject detached/self/chained/repeating snoozes. Preserve omissions, sign/units, order and source presence. Relative END requires explicit event DTEND or DTSTART/DURATION; an implicit all-day end or timed point is insufficient. Absolute/acknowledgement instants retain the ordinary whole-second profile. No firing instant or DATE recipient zone is selected by source preservation.

Omitted own alarm lists inherit in linked projections only; explicit own lists must match master definitions using the existing task policy. Do not infer progress, acknowledgement, cancellation or future alarm-state propagation. Retained alarms must remain valid after master/occurrence timing edits; reject incompatible edits instead of silently clearing source data. Keep AVAILABLE/VAVAILABILITY alarm rejection explicit despite shared timing helpers.

Propose 16 alarms per event component, 256 raw alarms per file/stored series, 100 additional repeats, 366-day equivalent duration/repeat-span bounds and the existing shared 65,536-code-point metadata budget. These bounded application limits do not claim full RFC support. Reuse immutable source text and new event signed-duration/alarm DTOs in nullable server-only metadata JSON, with no new columns/migration or canonical v2 reinterpretation. Existing readEventSource gates full source export/replacement; ordinary responses and hidden-only nodes remain private. Source replacements retain versions/baseline/no-op/conflict rules, and deletion scrubs active/private data.

Test trigger/anchor/state preservation, named/date/UTC contexts, repeat/snooze validity, own matching/omissions, shared budgets, unsupported/nested components/actions, immutable server state, native edit retention/rejection, privacy, atomic imports and source replacement/no-op. Extend real database/two-host/Flutter evidence. [RFC 5545 VALARM](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.6), [TRIGGER](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.6.3), [RFC 9074](https://www.rfc-editor.org/rfc/rfc9074.html) and the existing task alarm/snooze ADRs provide the scoped source baseline. This is not notification runtime or scheduling/client interoperability.
