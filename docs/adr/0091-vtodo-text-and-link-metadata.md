# ADR 0091: VTODO text and link metadata

Status: **scoped implementation of maintainer-confirmed metadata batch; concrete representation and limits remain under draft review**. Date: 2026-10-23.

The maintainer selected pure VTODO CLASS, URL and grouped CATEGORIES/COMMENT/CONTACT, with legal text annotations and retained source groups, before database import. Organizer/attendee data, relationships and alarms follow in dedicated profiles. This extends ADRs 0088/0090 without granting native authorization, assignment, contact editing or network access.

Proposed representation: immutable task-specific metadata and category groups on every raw component. Preserve source absence, category group order/value spelling/duplicates and per-group LANGUAGE; COMMENT/CONTACT retain per-property LANGUAGE/ALTREP. URL follows the existing bounded absolute HTTP/HTTPS, no-userinfo profile without fetching. CLASS accepts PUBLIC/PRIVATE/CONFIDENTIAL, retaining absence and canonical token projection; the label never enforces host authorization. Unknown extension classification tokens reject explicitly in this initial profile.

Retain progress-only occurrence boundaries: omitted metadata inherits in the linked projection, explicit metadata must match its master (complete grouped lists/order/annotations, URL and classification meaning). Explicit PUBLIC may match absent CLASS, whose RFC default is PUBLIC; no source property is inserted. Reject explicit differing metadata until content exceptions are designed. Keep optional progress independent.

Use existing task file-wide metadata budget, a 64-category-value cap and 32 comments/32 contacts per component, 4,096 code points per comment/contact, and existing bounded URI/category/text validators. No partial file on limits, malformed input or unsupported parameters. No tables, native editors, import/export endpoints, filters or HTTP feeds follow from pure wire support. Concrete mechanics remain draft-review material.

Validate escaped categories, repeated groups, Unicode/annotations, source presence/round trips, immutable values, occurrence inheritance/matching, URL/class rejection, unsupported participants/extensions/alarms, duplicates and file-wide budgets on VM/Chrome. See [RFC 5545 §3.6.2](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.2), [categories](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.1.2), [classification](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.1.3), [comments](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.1.4), [contact](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.2) and [URL](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.6).
