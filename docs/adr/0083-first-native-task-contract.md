# ADR 0083: First durable native task contract

Status: **maintainer-confirmed initial scope and completion/reopen/cancellation rules; concrete schema/API/query mechanics proposed**. Date: 2026-10-23.

After event export, implement non-recurring task CRUD and assignments first, with the Flutter example. Undated tasks and DATE/UTC/named-zone timing are included. Recurrence, original-occurrence progress/history and VTODO interchange follow in dedicated batches; unsupported recurring input must reject rather than disappear. Task dates/assignments do not book calendar time or initiate scheduling mail/notifications.

The maintainer selected completion at 100 percent with a server-recorded UTC completion time. Reopening returns NEEDS-ACTION/0 percent and clears the active completion timestamp. Cancellation preserves the current percentage and clears that timestamp. It describes the task's current completed state, not historical completion evidence. Completion history is a later feature; do not invent it from audit times. Preserve the previously confirmed independent task content, progress and assignment authorization boundaries; hosts may map them to shared rules.

Propose native UUID identity plus scrubbed active payload and minimal deletion marker, server-generated independent protocol identity, optimistic revisions and shared scope transactions. Content, progress and opaque host-validated assignees should use distinct commands and disclosure groups. Full actual parent/current/final proposal context must be available to replaceable host policy; an assignee reference grants no membership, attendee role or booking authority. Retain the whole-second [1970,2100) profile and pure core task timing semantics: optional start/due, positive duration only with start, no DUE plus DURATION, exact profile/zone, and no inferred due time.

Exact model fields, limits, progress actions, storage layout, pagination/cursor integration and migration mechanics require review as concrete implementation details. Reuse established dependency-blocked calendar deletion, stale-write rejection, final guarantee enforcement and no-total authorized page discipline. Validate focused temporal/permission/state tests, generated clients, populated/fresh schema, concurrent hosts and Flutter journeys before claiming the first implementation. No task runtime/schema is implemented by this record.
