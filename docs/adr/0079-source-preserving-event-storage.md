# ADR 0079: Source-preserving event storage implementation

Status: **Scoped implementation of confirmed ADR 0078 choices; concrete representation/migration mechanics under draft review**. Date: 2026-10-23.

Implement the storage prerequisite before the authenticated import endpoint. Keep native event UUID/actual parent/revision/deletion identity; change active protocol UID to exact text, add actual calendarId and fixed-size non-unique digest candidates, and compare exact UIDs under the durable scope lock. Preserve old UID spellings on upgrade. Native creation assigns the protocol UID; source conversion grants no authority or database writes.

Extend immutable event content with optional timed PERIODs and per-text annotations using existing CalendarTextParameters. Context validation freezes collections, preserves exact zone/end/duration meaning and charges the shared explicit-date budget. Normal native edits preserve periods/annotations by default; separate explicit replacement flags permit authorized changes/clears. Pattern/profile edits reject incompatible retained state and orphaned overrides. Calculation, original membership, previews and free/busy all use the same stored periods.

Store private current component/presence state separately from audit time. Public protocol-version values contain only sequence/stamp/created/modified; original occurrence version identities require both timing and protocol-identity disclosure. Text annotations follow their own text group; source STATUS/TRANSP presence follows state. Historical import baseline never appears in views or host policy snapshots. Add one optional, private, versioned canonical last-source snapshot on active data, populated only by accepted source conversion/import, not native creation or legacy initialization. Deletion scrubs the entire active row.

Native master checkpoints advance on actual master component changes, occurrence checkpoints on their own actual timing/cancellation/explicit repeated content changes. Stable normalized saves retain protocol state while existing accepted-write API revisions/audit behavior remains. Source versions and omissions are retained initially; native changed components advance effective sequence from zero when omitted, reject overflow, and use nondecreasing whole-second timestamps. New components get known creation time. Legacy masters initialize from known audit time with sequence zero; legacy occurrences omit unknown CREATED and use an explicitly documented modification-time initialization. No imported history/baseline is inferred.

Pure source conversion preserves the currently supported decoded master/override distinctions, arbitrary supported TEXT UIDs, DATE/UTC/named geometry, PERIODs, annotations, presence, independent versions and cancellation timing. Native effective CONFIRMED on omitted source STATUS is the selected application policy. Envelope/zone presentation is regenerated, not archived. Private baseline canonical v1 includes pinned IANA evidence and exact normalized component state, excludes native/audit/presentation identity, and is capped at 2 MiB UTF-8. Current source/presence state is validated independently; no event import/export endpoint, update/adoption, feed, scheduling or alarm action is added here.

Use pinned generation/migrations and verify fresh/populated schema behavior. Any SQL-only data-preserving transform must match the generated final schema, including text UID defaults/indexes; never edit generated metadata. Verify native retention and protected disclosure, exact UID/digest collisions, protocol no-op/change/overflow handling, full source conversion and baseline privacy/scrubbing, temporal/orphan/budget invariants, two-host/client and Flutter regressions. Record commands/results in the implementation/validation guides. APIs remain unpublished; no reset is assumed merely because breaking changes are authorized.
