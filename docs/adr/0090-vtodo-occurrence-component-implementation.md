# ADR 0090: VTODO occurrence component implementation

Status: **scoped implementation of confirmed ADR 0089; concrete mechanics remain under draft review**. Date: 2026-10-23.

Extend immutable task source values with original DATE/timed identity and expose immutable `IcalendarTaskSeries` with its master and linked `IcalendarTaskOccurrenceComponent` projections. Calendar tasks remain masters only, in master source order; preserve full original file/component ordering for reserialization. Overrides retain raw optional progress/checkpoints/content/timing, alongside resolved task milestones and inherited text/priority. No native effective progress or historical transition is synthesized.

Require exact source UID and original temporal profile. Validate all retained original targets with one aggregate generation per master and the shared file work budget; cap override components independently (64 by default) while `maxTasks` continues bounding total VTODO components. Duplicate originals reject even when source versions differ. Require explicit timing to match the projected current start/due; allow redundant supported end/duration forms only when their actual deadline agrees, retaining source form. Explicit text/annotations match; priority matches its source/default-undefined meaning. Ranges, timing/content differences and unprofiled metadata reject.

Exercise missing/detached masters, ordering, duplicate/excluded/absent/profile-mismatched originals, independent optional progress/checkpoints, inherited/repeated content/timing, due-only/start-only forms, duration and DST/fold deadlines, raw source presence, round trips, malformed input and aggregate bounds on VM/Chrome. No tables/endpoints, native task progress, assignments, imports, history or scheduling are changed by this pure adapter.
