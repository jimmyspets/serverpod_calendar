# ADR 0096: Source-preserving native task progress

Status: **scoped implementation of confirmed optional source progress/master defaults; concrete mechanics remain under draft review**. Date: 2026-10-23.

The maintainer selected independently optional STATUS/PERCENT-COMPLETE/COMPLETED in native task storage/responses, preserving unusual source combinations, with native commands retaining the agreed complete/reopen/cancel outcomes and no imported history. For recurring tasks the master is the default for originals with no own progress component; an explicit component retains its independently optional fields. Native occurrence actions replace only that occurrence's progress. Whole-series native progress commands remain rejected.

First prerequisite batch: make CalendarTaskProgress status/percentComplete nullable without deserialization defaults; completedAt stays optional UTC. Validate each present value independently, not source cross-field consistency. Existing JSON with explicit fields retains them; omitted fields remain absent. Native creation/reopening explicitly creates NEEDS-ACTION/0/no completion time, rather than relying on generated-model defaults. Native complete sets COMPLETED/100/server UTC, preserving the existing no-op only when all three completed fields already form that state. Cancel keeps the present/absent percentage and clears completion time; percentage commands set coherent unfinished state and clear completion time. Cancelled/completed status still requires reopen before percentage editing, and cancelled status before completion. Explicit actions may normalize unusual source fields; reads/content edits never do.

Remove the old neutral-recurring-master read invariant. Previews and first occurrence actions use stored master progress when no explicit occurrence row exists; explicit occurrence progress is not field-merged with master. Keep immutable actual/proposed host context and disclosure, original identity/membership, stale revision, conversion checkpoint and history/no-op rules. Native recurrence conversion still requires known clean checkpoint and explicit neutral progress. Existing occurrence history remains real native transitions; no history is inferred from source fields or audit times. Validate source-shaped before states individually and continue replay-validating actual command transitions.

Flutter displays missing source status/percentage as unspecified, never as stored defaults, with source completion state visible independently. Editing percentage requires an explicit value; native create/reopen still use agreed defaults. No import endpoint or full task metadata/version/baseline storage is added in this batch. These remain separate prerequisites. No database reset is implied. This pre-beta API break is authorized; regenerate all generated code with the pinned toolchain. Because progress is nested JSON, determine migration need from generated schema rather than inventing SQL.

Validate round trips of optional/unusual progress, coherent explicit commands/no-ops, inherited recurring defaults versus sparse occurrence rows, immutable/final authorization, history replay, disclosure and populated existing JSON.
