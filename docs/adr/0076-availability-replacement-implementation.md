# ADR 0076: Baseline-aware availability replacement implementation

Status: **Accepted active-row private snapshot/raw-read choices; concrete implementation mechanics under draft review**. Date: 2026-10-22.

The maintainer confirmed one server-only normalized source snapshot inside each definition's active-data row. It may retain values removed by local edits for exact conflict detection; ordinary views/exports never expose it and active-data deletion scrubs it. They also confirmed raw-read authority for existing-definition replacements. [ADR 0075](0075-availability-update-reconciliation-contract.md) remains the accepted scope/version/identity/no-op/permission/timestamp policy.

Use nullable `importBaseline` on the existing active record, with immutable server-only profile, canonical payload and optional source sequence fields. New accepted imports record the baseline transactionally. Old/native-created rows stay null: no history is invented and no database reset is necessary. Profile v1 includes the pinned IANA version; incompatible profiles reject replacement. Bound canonical UTF-8 payloads to 2 MiB and compare exact normalized values, without a digest-only equality shortcut. Canonicalization excludes native UUIDs/audit data, maps opening references to exact protocol UIDs, sorts opening/component identities and map keys, normalizes defined optional/grouped native representations, and preserves ordered metadata, original recurrence identities, temporal forms and independent component versions.

Replacement uses explicit parent/member revisions and exact file-to-selected-UID matching. Reuse currently matching opening UUIDs; new/reintroduced openings get new UUIDs. Require import, dedicated replacement and raw-read authority for each member; actual structural, metadata/protocol and occurrence-state changes additionally require their existing edit permissions. True no-ops retain all data/baselines/revisions/times/generation. Changed members advance API revision once, retain creation time, use database audit time, store exact incoming source protocol state and baseline, and bump scope generation once per changed batch. Parent metadata remains unchanged.

Trusted immutable host context includes current/final proposed state, baseline eligibility/profile/source version, local-change and changed classification, and retained/new/removed opening mapping, but not historical baseline payload. Preliminary and final host/organizer/extension checks apply even to no-op requests; receipts use final import/replacement/edit decisions independently of raw-read receipt flags. Return only host-approved member receipts with an explicit changed flag; no totals or hidden baseline/content disclosure. Existing generic sanitized failure codes remain in use: conflicts/no baseline/lower source sequence use dependencyConflict, malformed selection/profile uses validation, incompatible/corrupt baseline uses unavailable, and exhausted work uses limitExceeded.

Generate the nullable JSON column migration with pinned tools; keep old rows' baselines absent and verify fresh/populated schema behavior. No generated files or migration metadata are hand-edited. Full implementation/validation evidence is recorded in the update guide and validation record, without claiming broader synchronization, source adoption/overwrite, feeds or scheduling support.
