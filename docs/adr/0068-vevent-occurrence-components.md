# ADR 0068: VEVENT occurrence timing and cancellation components

Status: **Accepted timing/single-cancellation/THISANDFUTURE scope, in-file master requirement and content inheritance; API/limit mechanics under review**. Date: 2026-10-22.

## Context and confirmed scope

After [PERIOD additions](0067-vevent-period-additions.md), the maintainer selected single-occurrence timing/cancellation and timing-only THISANDFUTURE mapping to existing core values. Per-occurrence content changes and future cancellation remain explicit rejections. RFC 5545 [RECURRENCE-ID](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.4) identifies the original occurrence, not its moved start, and defines range ordering by original identity; separately overridden instances are independent of a range. [Native DATE ranges](0038-date-only-this-and-future-timing.md) and [timed series](0040-bounded-temporal-core-completion.md) already implement bounded timing semantics.

The maintainer explicitly selected an in-file matching master for every override, with omitted content inherited and supplied content differences rejected (except single cancellation). Keep this PR draft while API/limit mechanics remain under review. All ordinary whole-second/profile, exact zone and source/authorized-import boundaries remain unchanged.

## Implemented proposed adapter mechanics

Parse RECURRENCE-ID with legal VALUE/TZID and optional RANGE=THISANDFUTURE. Every component retains required UID, DTSTAMP and DTSTART under this METHOD-free standalone profile, including cancellation components. Identity and replacement timing must match the master's DATE or exact UTC/named/alias profile. Identity is always ordinary; replacement exclusive endpoints retain only the existing midnight-2100 exception. Floating/fractional/leap-second input, THISANDPRIOR, other range tokens, unknown parameters and duplicate identity parameters/properties reject.

Group exact decoded UIDs regardless of component order. Require exactly one in-file master per UID, with an explicit supported recurrence definition when overrides exist; reject detached components, duplicate masters and orphan/excluded identities. RRULE/RDATE/EXDATE belong to the master and reject on overrides. All component identities are validated against the unmodified effective master set, including earlier RDATE/PERIOD additions. Duplicate single/range anchors reject even if source SEQUENCE differs; no highest-version selection or scheduling reconciliation is performed.

IcalendarEventCalendar.events continues to expose master components. Its new immutable series list groups a master and raw typed overrides with core DateEventRangeSet or TimedEventSeries timing projections. Raw components retain RECURRENCE-ID, timing, content omission, protocol timestamps/SEQUENCE and source syntax. Common effective content is read from the master: omitted SUMMARY/DESCRIPTION/LOCATION/STATUS/TRANSP inherits; supplied text including LANGUAGE/ALTREP must exactly match decoded master values/parameters. A supplied STATUS must match the master's explicit status, except single STATUS:CANCELLED. TRANSP compares its opaque-default meaning. Other content differences reject rather than disappearing. Omitted end/duration remains the standalone DATE one-day or timed-point default, not inherited master length.

Single STATUS:CANCELLED removes the original identity from core timing output while retaining the component's typed timing/source. RANGE plus explicit CANCELLED rejects. Ranges preserve absolute civil/day shift and replacement end/duration/default form in original order, with later ranges replacing earlier shifts. Independent singles/cancellations remain independent; PERIOD spans retain existing native precedence beneath active range timing. Queries must use series overlap expansion to include moved-in and long occurrences, retaining caller-selected work/output limits. Core timing projections do not apply master cancellation/transparency or establish occupied/free intervals; callers must apply those semantics separately. This is not a native import, booking or free/busy adapter.

## Resource bounds and core propagation

The existing maxEvents default 128 counts all raw master and override components. Add maxOverridesPerEvent=64 per UID and maxValidationOccurrences=10000 for each membership scan, under the existing positive/hard-maximum configuration checks. Raw duplicates consume component/override caps before duplicate rejection. Shared default candidate work remains 200000 across zones, master alignment and all membership checks.

Pass optional RecurrenceWorkBudget through DATE/timed recurrence-set expansion and DATE single/range/timed-series construction. Local limits remain active, failures retain consumed shared work and existing callers that omit it retain behavior. DATE singles/ranges may use separate bounded scans, both charged to the shared object; this is no claim of one universal scan. Query-time budgets remain independently caller-selected and are not silently attached to parsed series. Membership overflow or any late component/content/identity error returns no partial calendar and sanitized diagnostics.

## Alternatives, consequences and acceptance

Detached components require trusted storage lookup and revision/identity reconciliation, which belong to authenticated import. Choosing by source SEQUENCE would silently reconcile histories without policy. Dropping changed content would lose supported-looking data; reject it while retaining accepted raw omission/source. Flattening ranges or validating moved starts would change identity and miss moved-in queries. Optional aggregate core budgets prevent repeated per-series validation from multiplying the parser's work cap without changing native callers.

Test DATE/UTC/named grouping and round trips, single move/resize/cancellation, independent ranges/singles, nominal DST and PERIOD behavior, original membership versus actual starts, content inheritance/mismatch, source version retention, duplicate/orphan/excluded/context rejection, profile edges, combined caps, cross-series aggregate work and atomic private-free diagnostics. Run focused affected regressions during development and full VM/Chrome/repository checks once complete. No schema, migration, generated protocol/client or dependency changes follow. Database import/export, per-occurrence content/future cancellation, scheduling/alarms, HTTP feeds and external-client compatibility remain pending.

## Scoped supersession, 2026-10-24

[ADR 0106](0106-single-event-content-overrides.md) now adds selected event occurrence text/annotations and anchor-only content with timing inheritance and lossy-export rejection. It supersedes the earlier text-difference rejection/pending notes only for that scope. The private event-source-v2 baseline rejects older imported v1 data explicitly; no automatic reset/adoption occurs. The earlier timing, lifecycle and unsupported-feature boundaries otherwise remain in force.
