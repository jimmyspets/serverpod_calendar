# ADR 0109: Inert event source references

Status: **confirmed inert source-reference scope; concrete representation and limits under draft review**. Date: 2026-10-24.

The maintainer selected the existing task policy for VEVENT RELATED-TO and URI ATTACH. Preserve unresolved source UID references, including missing/self/cyclic references, and inert file URIs with optional media types. No native graph edge, identity mapping, authority, dependency rescheduling, cascade deletion, fetching or file access follows. Native graph/file editors and publication mapping remain separate.

Reuse bounded PARENT/CHILD/SIBLING relationships (default PARENT with source omission retained), URI-only attachments with optional explicit VALUE=URI and FMTTYPE, ordered duplicates and immutable decoded values. Other relation types/parameters, inline binary/data payloads and unknown parameters reject. Targets allow 4,096 code points, URIs use the existing absolute ASCII/no-userinfo profile up to 4,096 characters, media type/subtype tokens allow 127 characters without parameters/wildcards, and each list allows 64 values. Share the existing event metadata code-point budget across a file or stored series. These are application-profile limits, not RFC maxima.

Omitted own lists inherit in linked projections only. Explicit lists must match the master in order and target/effective relation or URI/case-insensitive media-type meaning; redundant explicit PARENT/default URI may match while retaining source presence. Different occurrence references reject, including future timing anchors. An unresolved reference never proves that its target exists or is accessible.

Extend existing server-only event source JSON with nullable reference lists and immutable relationship/attachment DTOs, preserving older metadata-only/participant v2 baselines. No table columns or migration are proposed. Existing readEventSource authority gates export/replacement; ordinary responses/hidden-only nodes remain private. Native edits/timing transfers preserve references and component history, and inherited-timing export still rejects lossy states. Source replacement retains baseline/no-op/local-conflict semantics; deletion scrubs active/private snapshots without traversing source links.

Validate decoded round trips, omissions/default presence, malformed/unprofiled/binary/data rejection, shared limits, immutable host/storage intents, own matching, privacy, native retention, no-op/conflicts and atomic imports. Extend database, two-host and Flutter export evidence. See [task policy](0093-vtodo-source-references.md), [RFC 5545 RELATED-TO](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.5) and [ATTACH](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.1.1). Native graph behavior, RFC 9253 extensions, alarms, feeds and scheduling remain separate.

Compatibility finding during this batch: canonical v2 normalization omits empty maps, including required empty participant parameter maps. Restore only those known master/own participant paths before generated baseline decoding, without changing canonical bytes, source versions or address/parameter claims. Reject malformed/noncanonical state normally. Add parameter-free master/own and import/replacement regressions; this is a decoder correction, not baseline adoption or a database reset.
