# ADR 0092: VTODO source participants

Status: **scoped implementation of confirmed source/assignment separation; bounded concrete mechanics remain under draft review**. Date: 2026-10-23.

The maintainer selected source-preserved ORGANIZER/ATTENDEE calendar addresses, separate from native task assignments. Reading/importing their claims grants no authority, assigns nobody, expands no groups, sends no messages and proves no membership, delegation or acting-sender permission. Future host-identity mapping requires a separate authorized action. Task iTIP/iMIP remains excluded under ADR 0011; METHOD continues rejecting.

Propose immutable `IcalendarTaskParticipants` and sealed `IcalendarTaskParticipant` values with concrete `IcalendarTaskOrganizer`/`IcalendarTaskAttendee` with original syntax, exact address and frozen decoded parameter maps. Organizer permits CN/LANGUAGE/DIR/SENT-BY; attendees additionally permit CUTYPE/MEMBER/ROLE/PARTSTAT/RSVP/DELEGATED-TO/DELEGATED-FROM. Freeze address lists, preserve source order/duplicates/parameter presence/spelling and validate existing absolute URI/no-userinfo syntax. Use no case or mailbox guessing. A master with attendees requires an organizer; occurrence components may inherit it from the same-file master.

Expose optional source CN/language/directory/acting-sender, raw optional token values and RSVP, plus separately named effective attendee CUTYPE/ROLE/PARTSTAT/RSVP RFC defaults/fallbacks. Unknown well-formed token values are retained, with UNKNOWN/REQ-PARTICIPANT/NEEDS-ACTION fallbacks respectively; no custom semantics are activated. PARTSTAT includes task-specific COMPLETED/IN-PROCESS and remains separate from task STATUS/progress/history. Source OPTIONAL progress fields remain independent.

Bound addresses to 1,024 ASCII characters, CN to 4,096 code points, token values to 64 ASCII alphanumeric/hyphen characters, 64 attendees per component and 16 addresses per list parameter. LANGUAGE requires CN and a valid existing tag. One instance per allowed parameter, single-valued except the three list parameters; RSVP TRUE/FALSE only. All decoded participant addresses/parameters charge the existing file-wide task metadata budget. Unknown parameters, malformed claims and limit exhaustion reject the whole file without partial results.

Retain progress-only occurrence policy: absent organizer/attendees inherit only in linked projections; explicit complete participant state must match exact addresses, ordered lists and decoded parameter presence/values (token case insignificant). Explicit participant state differences, including PARTSTAT, reject until content exceptions are designed. This deliberately also rejects redundant default-parameter additions in an override; source presence is preserved instead of merged. No host authorization or native schema/API changes belong to this pure batch. Relationships, attachments, private extensions and alarms remain separate.

Validate source preservation/defaults/fallbacks, all task participation states, multiple address-list values, duplicate/malformed/illegal parameters, exact identity and occurrence matching, immutable values, shared budgets and no METHOD/VALARM support on VM/Chrome. See [RFC 5545 attendee](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.1), [organizer](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.3), [participation status](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.2.12) and [role](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.2.16). Concrete mechanics remain under draft review.
