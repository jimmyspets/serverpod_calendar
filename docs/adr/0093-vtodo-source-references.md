# ADR 0093: VTODO source relationships and attachments

Status: **scoped implementation of confirmed inert source-reference policy; concrete representation/limits remain under draft review**. Date: 2026-10-23.

The maintainer selected RELATED-TO as an unresolved source UID reference and ATTACH as an inert URI with optional media type. Missing, self-referencing and cyclic source links may be preserved as data; no graph is resolved or native link created. Native graph validation, independent target/file access, host-identity resolution and publication UID mapping remain separate. No dependency scheduling, cascade deletion, fetching or implicit file access is activated.

Propose immutable `IcalendarTaskReferences` on raw components, containing ordered `IcalendarTaskRelationship` and `IcalendarTaskAttachment` values with original syntax. RELATED-TO supports nonempty decoded text UID targets up to 4,096 code points, optional PARENT/CHILD/SIBLING RELTYPE, absent type preserved with separately named effective PARENT. Other RFC 9253 relations/parameters and unknown types reject until profiled; no blanket extension support follows.

ATTACH supports the existing absolute ASCII URI/no-userinfo profile up to 4,096 characters, optional explicit VALUE=URI and optional FMTTYPE. Reject VALUE=BINARY, ENCODING and data-scheme payloads; no embedded calendar file bytes or automatic MIME copying. Preserve raw URI spelling, source VALUE presence and declared media type. Media types are bounded type/subtype tokens up to 127 characters without parameters or wildcard ranges; declared values do not verify content. Opaque storage/CID/URN references may remain inert URI data.

Cap each list at 64 values per component and charge decoded targets/URIs/RELTYPE/media type against the shared task metadata budget. Preserve duplicate references and source order. Omitted occurrence reference lists inherit only in linked projections; supplied complete lists must match target/type or URI/media-type meaning and order. Redundant explicit PARENT/default URI representation may match while retaining source presence. Explicit content differences reject under ADR 0089. No tables, native editors, authenticated task import/export or file-storage service are implemented by this pure profile.

Validate forward/dangling/self/cyclic text references without lookup, exact UID spelling, default/explicit relation presence, URI/media forms, immutable lists, round trips, occurrence inheritance/matching and shared bounds on VM/Chrome. Test rejection of binary/data payloads, malformed URIs/media tokens and unprofiled extended relations. See [RFC 5545 RELATED-TO](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.5) and [ATTACH](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.1.1). Concrete representation/limits remain under draft review.
