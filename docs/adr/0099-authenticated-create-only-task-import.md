# ADR 0099: Authenticated create-only task import

Status: **scoped implementation of confirmed ADR 0097 choices; concrete API/transaction mechanics under draft review**. Date: 2026-10-23.

Implement a login-required `calendarTask.importTasks` operation after ADR 0098 storage. Immutable `CalendarTaskImportRequest` contains actual destination calendar UUID, expected parent revision and ByteData. `CalendarTaskImportResult` contains only final-approved minimal task receipts, with no totals or implied detail access. Reject empty batches. Snapshot the exact bounded byte slice before awaiting host policy; retain strict UTF-8/CRLF input without byte-API repairs.

Resolve trusted host actor/scope and actual active destination, check import authority/revision before parsing, then parse and convert the complete supported VTODO file with aggregate raw-component/recurrence/text/alarm limits. Allocate new native task UUIDs independently of source UID. The immutable `CalendarTaskImportIntent` contains all validated members, each with native UUID, exact protocol UID and complete current source state; no private historical baseline appears in policy context. A dedicated import permission plus create authority for each member is required, and change-task-progress authority whenever any master/occurrence supplies STATUS, PERCENT-COMPLETE or COMPLETED, including explicit neutral fields.

Reopen the durable scope transaction, reread the actual parent/revision, authorize complete immutable batch/member proposals and bound destination work with maxScannedTasks. Compare exact active protocol UIDs within destination calendar after non-unique digest candidate selection; retain copies into other calendars. Check final declared-guarantee authority and trusted context before atomic persistence. Final external checks retain the documented revocation race; no process-local correctness cache or weaker fallback is introduced.

Persist source master content/progress/version, raw per-original source components/progress/versions and a private canonical baseline. Record native revision 1 and database audit time separately. Preserve optional source timestamps/sequence exactly. Set prior-progress checkpoint unknown, including neutral non-recurring tasks. Assign nobody, create no transition history and do not arm alarms, acknowledge native actions, fetch URIs or send scheduling messages. Return only receipts whose batch/member final decisions all permit disclosure; bump scope generation once, leaving parent metadata revision/time unchanged. Any parse, limit, conflict, denial or persistence failure rolls back the entire batch.

The example adds a text-paste screen with an explicitly disclosed CRLF conversion and synthetic VTODO example. Text-editor normalization does not relax the strict byte endpoint. Source participants and alarms remain inert; no new rich-source detail editor/disclosure is implied. Source replacement/adoption, task export, feeds, native alarm execution and VTODO scheduling remain separate.

Use pinned generation for request/result and endpoint clients; no table changes/migration are required after ADR 0098. Verify byte slices, empty/invalid/over-limit rejection, independent/neutral/occurrence progress gates, final revocation and immutable whole-batch context, atomicity, exact UID/digest/copy conflicts, source retention/baseline privacy/deletion/unknown conversion, and generated-client two-host UID/parent races plus the Flutter import journey. Run focused checks during implementation and the complete native batch checks before committing. Passing import tests does not establish alarm activation, export or external-client interoperability.
