# ADR 0060: Availability organizer, text parameters and private extensions

Status: **Accepted batch choices; DTO/adapter mechanics under review**. Date: 2026-10-21.

## Context and sources

The native availability implementation under [ADR 0059](0059-availability-occurrence-edits-and-metadata.md) stores legal plain-text metadata and opening edits. The selected [RFC 7953 profile](../rfc/rfc-7953.md) also requires host-validated organizer metadata, legal shared text parameters and explicitly supported extensions. The maintainer subsequently approved dedicated organizer approval, annotations on existing text and host-validated private X-properties. The scoped implementation is documented in [the guide](../availability-publication-metadata.md); interchange remains separate.

[RFC 7953 section 3.1](https://www.rfc-editor.org/rfc/rfc7953.html#section-3.1) permits ORGANIZER on VAVAILABILITY, not AVAILABLE. SUMMARY, DESCRIPTION and LOCATION remain singular in each component. COMMENT and CATEGORIES can repeat. The shared [RFC 5545 property decisions](0010-rfc5545-property-decisions.md) select LANGUAGE in legal contexts, ALTREP with retained ordinary text, CN as display metadata and DIR as a URI reference without lookup. Registration alone does not enable an IANA extension; private X-properties require trusted host registration and validation.

## Maintainer-selected batch

1. Add optional definition-only organizer metadata with calendar address, optional common name, optional language for that name and optional directory URI. Require ordinary metadata permission and a dedicated host address-approval check using trusted actor/scope, actual parent/current definition and final validated proposal. Approval does not grant calendar access, identify a host user, book a resource or initiate scheduling. The maintainer selected this dedicated adapter check.
2. Attach optional LANGUAGE/ALTREP to the existing supported text properties while preserving ordinary text and legal multiplicity. Use LANGUAGE alone for categories; ALTREP is not a standard CATEGORIES parameter. A language tag does not create translated variants, perform translation or change UI language. The maintainer selected this annotation approach. DTO representation and URI editing limits remain reviewable mechanics; preserve text/parameter association through edits, including repeated comments/categories.
3. Add a bounded trusted host registry for private X-properties in explicitly allowed definition/opening contexts. Reject unregistered names, invalid values, unsupported parameters and budget overflow atomically. Registered IANA properties remain unavailable until individually profiled and implemented. The maintainer selected this private-extension increment. Do not accept client-defined registries or allow metadata to override timing, authorization, identity or scheduling semantics.

SENT-BY and acting-sender authority remain separate scheduling work. CONTACT remains import-preserved only and cannot be authored through ordinary native metadata editing. Parsing/export, feed projections, protocol timestamps/SEQUENCE, envelope duration shorthand, occurrence-specific content and future cancellation remain separate batches.

## Native mechanics and alternatives

Keep optional additions decodable from existing typed JSON without changing existing identities, revisions, timestamps, timing overrides or geometry on reads. Generation and both module CLI/host MCP migration checks found no table-layout changes; no migration is generated for these nested JSON additions. Freeze all nested collections before host callbacks and apply raw count, individual value and aggregate metadata budgets before normalization. Ordinary timing editors must preserve unrelated metadata; stale revisions reject rather than merge silently. Native APIs are unpublished, so a reviewed breaking DTO change is preferable to ambiguous parameter-to-text association.

Organizer approval must fail closed on missing adapters, denial, errors or timeout. The adapter applies at preliminary/final writes under [ADR 0045](0045-authorization-consistency-guarantees.md); an external final check still has an after-check revocation race. Unchanged organizer retention is not evidence of current publication authority. Future feed/scheduling adapters must check their own continuing publication/acting authority.

Alternative: use general metadata authority alone for organizer changes. This has a smaller integration API but conflates permission to edit descriptive text with permission to publish a particular calendar address. Alternative: defer all extension storage until interchange; this reduces this batch but postpones host metadata retention. Alternative: translated property collections; these need a separate native translation contract and must not imply illegal repeated wire properties.

## Acceptance conditions

Test legal property/component placement; language-tag validation and spelling preservation; singular property cardinality; ALTREP with retained ordinary text and no retrieval; distinct annotations on repeated values; organizer address approval independently of metadata rights; actual parent/current/proposed immutable context; final denial/timeout and stale-write atomicity; configured/unconfigured extension values and contexts; attempts to override core semantics; raw and aggregate limits; metadata retention through timing edits; unchanged calculated free/busy and private summary results.

Verify older stored JSON, generated server/client APIs, two-host mutation visibility and races, and the Flutter metadata journey. Run focused tests during implementation, then the agreed broader batch checks. Record actual results separately from proposed acceptance conditions. Do not claim wire round trips, external-client interoperability, mail delivery or full RFC 7953 support from this native increment.

## Implemented representation and bounds

Add optional `textParameters` and `extensions` to definition/opening content, plus optional definition-only `organizer`. Existing text fields stay plain strings. The parameter block contains singular summary/description/location parameters, one language tag for the component's native category group, and optional position-aligned comment parameters. A nonnull comment-parameter list must have exactly the comment count; entries can be null. Parameters cannot exist without their ordinary property. Repeated wire CATEGORIES grouping and import-preserved CONTACT need a later source/interchange representation; this native profile does not claim to preserve arbitrary wire property grouping.

Use the existing BCP 47 well-formedness validator, preserving spelling without registry lookup/canonicalization. ALTREP/DIR/address values use bounded absolute ASCII URI syntax, rejecting whitespace, malformed percent escapes, relative references and embedded user information. No scheme is fetched or rendered. Organizer address is at most 1024 characters; alternative/directory URIs 4096. CN is at most 4096 code points; its optional LANGUAGE requires CN. SENT-BY is absent.

`approveAvailabilityOrganizer` is a required host-policy method returning allow/deny/unavailable; it is called independently when current or proposed organizer exists, including removal and unrelated full-content replacements. It sees actual immutable current/final proposed state, transaction and authorization phase. Preliminary calls follow ordinary permission checks; final approval follows final ordinary authorization and is followed by trusted-context verification. Adapter errors/timeouts fail unavailable; denial fails access denied. It must meet the policy's declared guarantee and never perform side effects. Occurrence-only actions retain metadata without reauthoring it; future publication/scheduling checks remain separate.

Install up to 32 immutable private-name registrations with explicit definition/opening contexts and a side-effect-free decoded-TEXT validator. Names are compared case-insensitively, retain supplied spelling, and use the native `X-` plus alphanumeric/hyphen profile at most 64 characters. Each component has at most 32 raw distinct names; each value has at most 4096 code points. No custom property parameters or duplicate-name instances are exposed in this first native profile. Raw metadata, including parameters, organizer and extensions, shares the existing 65536-code-point definition budget. Unknown IANA names fail the private-name validator; unknown private registrations/contexts/invalid values fail writes. Validator errors fail unavailable. Validation applies to the complete proposal at preliminary/final content writes. Registry changes do not erase stored metadata or reinterpret opening geometry; stored raw syntax is validated on reads, while publication authorization remains host-owned.

The demo approves only `urn:calendar-example:user:<trusted principal>` or organizer removal, and registers one synthetic `X-CALENDAR-EXAMPLE-LABEL` for both contexts. It has no address directory or real-email behavior. The Flutter metadata editor stores annotations per property/comment and removes comment annotations with that comment. Timing forms preserve all new fields. Clearing a text property with retained parameters fails validation until the parameters are explicitly cleared, avoiding silent loss.
