# ADR 0080: Authenticated create-only event import

Status: **Scoped implementation of confirmed ADR 0078 choices; concrete API/transaction mechanics under draft review**. Date: 2026-10-23.

Build on ADR 0079 storage and the accepted pure wire profile. Add an authenticated event import endpoint with bounded copied bytes, actual destination calendar UUID and expected parent revision. Strict full-file parsing precedes writes; no partial import or compatibility repair. A text editor may explicitly convert its textarea line endings to CRLF. Preserve all currently supported decoded event/override semantics, independent source versions/omissions and private source baseline. Native IDs are newly server-assigned, distinct from exact source protocol UIDs.

Require independent importEvents authority and createEvent for every proposed series, plus changeEventStatus when a master or single component is cancelled. A cheap import check and parent revision check precede parsing; full immutable proposed-batch context is used for preliminary and final authorization under the durable scope transaction. Requests carry actual parent state, assigned native event ID and final validated content/override/protocol state. Never include historical baseline payload. Rights to import do not grant read/export or permission to mutate existing objects.

Authorize all proposals before disclosing destination UID conflicts. Scope conflicts to exact active UID strings in the actual destination, using fixed-size digest candidates and exact equality under the shared lock; separate-calendar copies are allowed. Duplicate masters and detached/unsupported components reject under the pure profile. Count the existing raw maximum 128 VEVENT components, including overrides, and the existing per-series explicit-date/override/work limits. Imports additionally refuse to exceed the configured destination maxScannedEvents budget (default 1,000 active series), without exposing counts. This is a bounded import profile, not a new universal native storage capacity.

Apply all new rows, source checkpoints and one private baseline per series atomically, at native revision 1 and one database audit time. Advance scope generation once; parent metadata/revision/time stays unchanged. Require final current context and the configured coordinated/fresh-check guarantee, with no downgrade; external policies retain their residual revocation race. A failed or denied later member leaves nothing committed. Importing source UID/version/address values activates no scheduling, feeds, network retrieval or alarms.

Return only final-approved minimal receipts for members whose batch/create/lifecycle decisions all allow receipt disclosure. No source values, hidden totals or implicit detail access. An undisclosed successful import may return an empty receipt list; retry after a committed response loss may conflict. No idempotency ledger or update/adoption flow is added. Native edits and deletion retain ADR 0079 lifecycle/privacy rules.

Verify source semantics, atomic late rejection, raw limits and mutable-byte ownership, permission independence and full trusted context, stale/deleted/foreign parents, exact/scoped UID and injected digest collisions, hidden receipts/baselines, calculation integration and multi-host import/delete races. Exercise generated-client and Flutter import/duplicate/rejection journeys. Reuse the schema from ADR 0079; no new table or migration is required. Keep event export/replacement and scheduling separate.
