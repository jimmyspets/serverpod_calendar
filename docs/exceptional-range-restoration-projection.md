# Exceptional range restoration projection

[ADR 0186](adr/0186-exceptional-range-restoration-projection.md) describes the approved pure projection. `projectPublishedExceptionalRangeRestoration` accepts an untrusted complete REQUEST and an exact original anchor. It retains a moved single component at that original and, when representable, adds a future component at the next original using the underlying series timing. An EXDATE anchor remains excluded; an exclusion is not proof of a cancellation, prior publication, identity or authority.

The implementation validates both complete messages, fixed participant claims, retained component versions and source properties, and compares effective native occurrence values across a completely enumerated finite recurrence. Its first profile requires an explicit SEQUENCE and matching organizer/attendee addresses on each component; it does not claim those are universal RFC requirements. DATE, UTC and exact pinned named-zone profiles, source exclusions and finite PERIOD additions are handled within the existing byte, component and shared-work limits. UNTIL rules must be provably inside the supported horizon. COUNT rules are accepted only after the engine accounts for every counted original; generated daylight-saving gaps do not consume COUNT. Unbounded rules, unprovable horizons, collisions, unsupported source metadata and exhausted limits reject the complete candidate. The first successor cannot currently be an independently edited single or a special PERIOD without a suitable existing range; those and other cases reject when source distinctions cannot yet be proved unchanged.

New projection components copy the source master's SEQUENCE and DTSTAMP for this pure candidate. They are not allocated collision-safe outgoing versions and must not be treated as ready-to-send durable publications. This is a pure helper: it does not prove that any cancellation occurred, allocate durable publication versions, modify an event, authorize a recipient or send a message. The existing durable guard remains in force. Separate review is required before durable integration. See [the investigation](range-anchor-restoration-investigation.md) and [actual validation](validation-exceptional-range-restoration.md).
