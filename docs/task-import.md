# Task import contract and prerequisites

[ADR 0097](adr/0097-create-only-task-import-contract.md) records the confirmed first import scope. **Authenticated create-only task import is now implemented under [ADR 0099](adr/0099-authenticated-create-only-task-import.md).** [Source storage](task-source-storage.md) follows under ADR 0098. [Optional native progress](task-source-progress.md) and the [pure wire adapter](icalendar-task-adapter.md) remain separate implemented prerequisites.

The endpoint atomically creates complete supported task series in one actual destination calendar. Exact protocol UID conflicts with an active task in that calendar reject the whole batch; copying the same UID into another calendar remains possible. Server-generated native API UUIDs are separate. Updates, reconciliation and scheduling remain separate operations.

Require dedicated import authority plus create permission for every series. Require progress permission whenever any source master/occurrence includes STATUS, PERCENT-COMPLETE or COMPLETED, even explicit neutral values. Supply immutable complete proposals and actual parent/current context, honor the declared consistency guarantee and recheck before committing. Minimal receipt disclosure is separate from task detail access. Concrete limits, source storage and validation evidence are described below.

Preserve source versions/omissions for each master/occurrence and record a private normalized baseline in active storage. API revision/audit time are separate. Source progress is independently optional; unrecorded originals use master progress, while explicit components retain their own full sparse value. Import creates no historical transitions. Imported non-recurring tasks keep an **unknown prior-progress checkpoint**, even with neutral current progress. Conversion to recurrence remains blocked until a future explicit adoption/reconciliation policy is implemented; import never establishes that the task has always been clean. Source participants assign nobody/prove no identity; source alarm/acknowledgement/snooze data remains unarmed and unverified; relationships and files are inert references. No fetching, invitations, task scheduling or automatic activation follows.

Storage preserves annotations/groups, participants, references/attachments, alarm/snooze definitions, component source presence/timing forms and independent versions. Follow decoded semantic preservation with future envelope/pinned-zone regeneration, rather than promising original file bytes. The private baseline is excluded from ordinary views/host snapshots/receipts/current exports and scrubbed with deletion; source versions do not authorize or prove freshness. Native/legacy tasks get no invented import baseline. Replacement/adoption and source reconciliation remain later contracts.

[Source storage](task-source-storage.md) under [ADR 0098](adr/0098-task-source-storage-model.md) now retains current decoded components and a separate private baseline representation. The maintainer selected source preservation now with native editors later, and no protocol-version change for assignment-only edits. The importer must populate this storage atomically with the confirmed unknown prior-progress checkpoint; the endpoint now follows under ADR 0099, with validation evidence below.

Endpoint acceptance conditions include independent/final authorization, atomic rollback, bounded strict rejection, exact UID/copy/race handling, source-preserving progress/versions, private baseline/deletion, no invented history/assignment/activation and real generated-client/two-host/Flutter journeys. The implemented import results below are separate from pure parsing/progress prerequisite evidence.

## Implemented create-only operation

`calendarTask.importTasks(CalendarTaskImportRequest)` requires a logged-in endpoint session and trusted host context. Supply actual destination calendar UUID, expected parent metadata revision and strict bounded ByteData. The service copies exactly the byte slice before policy awaits. It checks import permission/revision before parsing, then rereads the actual active parent and authorizes complete immutable batch/member source proposals under the durable scope transaction. Empty batches, unsupported data and any unavailable/denied member reject without partial creation.

Require `importTasks` plus `createTask` for each member. Add `changeTaskProgress` whenever any master/occurrence supplies STATUS, PERCENT-COMPLETE or COMPLETED, including NEEDS-ACTION and zero. Source-only participant data does not require assignment authority because no native assignees are created. Final batch/create/progress decisions independently control minimal receipt disclosure; a successful import may return no receipts, and receipts grant no task detail access. Historical baselines never appear in policy proposals or result DTOs.

The 1 MiB byte cap and existing pure wire raw-component, override, text, recurrence and alarm budgets apply to the whole file. Destination work is separately bounded by `maxScannedTasks`, including newly proposed masters. Exact active protocol UID conflicts are destination-local after bounded non-unique digest candidate lookup; copying the same UID into another calendar remains valid. Tombstone UUIDs are never reused; a deleted source UID may be imported as a new native task. Conflicts and limits disclose no totals or partial result lists.

Source master and raw occurrence content/progress/versions are retained without native completion defaults or source timestamp corrections. Record API revision 1 and database audit time separately, keep prior progress unknown, and create no transition history. Inert participant, URI, relationship and alarm/acknowledgement/snooze values stay source data: no assignment, fetch, invitation, firing time or notification is produced. A private normalized last-source baseline is created and retained unchanged through later native edits; deletion scrubs it with active source/history data. Import advances scope generation once and leaves parent metadata revision/time unchanged.

Every final request carries the complete validated batch, actual parent, server-generated native identities and current proposed source state. Declared coordinated/external policy guarantees and context revalidation apply, without silent downgrade. External fresh checks retain their after-check revocation race. Transaction/UID/parent correctness uses the database scope lock, not local caches or sticky routing.
