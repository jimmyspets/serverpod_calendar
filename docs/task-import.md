# Task import contract and prerequisites

[ADR 0097](adr/0097-create-only-task-import-contract.md) records the confirmed first import scope. **The authenticated endpoint is not implemented yet.** [Source storage](task-source-storage.md) now follows under ADR 0098. [Optional native progress](task-source-progress.md) and the [pure wire adapter](icalendar-task-adapter.md) are implemented prerequisites, not an authenticated import service.

The first endpoint will atomically create complete supported task series in one actual destination calendar. Exact protocol UID conflicts with an active task in that calendar reject the whole batch; copying the same UID into another calendar remains possible. Server-generated native API UUIDs are separate. Updates, reconciliation and scheduling remain separate operations.

Require dedicated import authority plus create permission for every series. Require progress permission whenever any source master/occurrence includes STATUS, PERCENT-COMPLETE or COMPLETED, even explicit neutral values. Supply immutable complete proposals and actual parent/current context, honor the declared consistency guarantee and recheck before committing. Minimal receipt disclosure is separate from task detail access. Exact limits/models/source-storage representation and implementation evidence follow in subsequent increments.

Preserve source versions/omissions for each master/occurrence and record a private normalized baseline in active storage. API revision/audit time are separate. Source progress is independently optional; unrecorded originals use master progress, while explicit components retain their own full sparse value. Import creates no historical transitions. Imported non-recurring tasks keep an **unknown prior-progress checkpoint**, even with neutral current progress. Conversion to recurrence remains blocked until a future explicit adoption/reconciliation policy is implemented; import never establishes that the task has always been clean. Source participants assign nobody/prove no identity; source alarm/acknowledgement/snooze data remains unarmed and unverified; relationships and files are inert references. No fetching, invitations, task scheduling or automatic activation follows.

Full storage must first preserve annotations/groups, participants, references/attachments, alarm/snooze definitions, component source presence/timing forms and independent versions. Follow decoded semantic preservation with future envelope/pinned-zone regeneration, rather than promising original file bytes. The private baseline is excluded from ordinary views/host snapshots/receipts/current exports and scrubbed with deletion; source versions do not authorize or prove freshness. Native/legacy tasks get no invented import baseline. Replacement/adoption and source reconciliation remain later contracts.

[Source storage](task-source-storage.md) under [ADR 0098](adr/0098-task-source-storage-model.md) now retains current decoded components and a separate private baseline representation. The maintainer selected source preservation now with native editors later, and no protocol-version change for assignment-only edits. The importer must populate this storage atomically with the confirmed unknown prior-progress checkpoint; the endpoint and its acceptance evidence remain separate.

Required endpoint evidence includes independent/final authorization, atomic rollback, bounded strict rejection, exact UID/copy/race handling, source-preserving progress/versions, private baseline/deletion, no invented history/assignment/activation and real generated-client/two-host/Flutter journeys. None of these future endpoint tests is claimed by pure parsing or the progress prerequisite.
