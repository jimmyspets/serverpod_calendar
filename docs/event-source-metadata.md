# Read-only event source metadata

Status: scoped implementation under [ADR 0107](adr/0107-read-only-event-source-metadata.md), following the confirmed source-first, independent source-read and task-style occurrence choices. Concrete mechanics remain under draft review; actual commands and results are recorded in [the validation record](scaffold-validation.md).

The VEVENT adapter and authenticated import/export/replacement preserve CLASS, URL and separate CATEGORIES/COMMENT/CONTACT groups. Category spelling, duplicate values, grouping/order and optional LANGUAGE stay intact; comments and contacts retain decoded TEXT and legal LANGUAGE/ALTREP annotations. This preserves decoded semantics, not an original file archive. The envelope and zones still regenerate. Native field editors for these values remain separate; ordinary text, timing, lifecycle and recurrence edits retain them. CONTACT remains source-only, without a directory or native contact editor. No URI is fetched and no source label grants permission, resolves a host identity or starts mail, feeds or reminders.

The initial profile accepts standard PUBLIC/PRIVATE/CONFIDENTIAL labels and absolute HTTP/HTTPS URLs without embedded credentials. Other legal RFC labels, URI schemes and unprofiled parameters reject explicitly. CLASS omission stays absent in storage/output, with RFC effective default PUBLIC. Omitted occurrence metadata inherits. Explicit occurrence values must match the master, including source grouping and annotations; explicit PUBLIC can match an omitted master CLASS. Differing occurrence metadata rejects, including at a THISANDFUTURE timing anchor. The pure series `metadataFor(component)` resolves this bounded inheritance without inserting omitted source properties and rejects foreign components.

Each component allows at most 64 category values and 32 each COMMENT/CONTACT, with existing text/language/URI limits. A shared 65,536-code-point metadata ceiling covers all master/occurrence components in a wire file. Native protocol validation also bounds each stored series with one shared metadata budget. Failures return no partial file/import; limits are application-profile limits, not RFC maxima.

## Storage and native editing

Immutable server-only metadata, category-group and annotated-text DTOs live in existing event JSON. Master metadata is in `CalendarEventProtocolState.sourceMetadata`; own component metadata is in nullable `sourceMetadata` fields on single/future override DTOs with per-field `scope=serverOnly`. Pinned generation verifies that server storage JSON retains them and protocol JSON omits them; database tests verify persistence. There are no new table columns/migrations or client metadata DTOs. Existing event-source-v2 baselines without nullable metadata remain compatible. New canonical baselines include source metadata for exact no-op/local-conflict detection; historical snapshots remain private and deletion scrubs the entire active payload.

Native commands cannot set this source data directly. They preserve it through selected text edits, cancellation/restoration and single/future timing scope transfers, including component creation/version history. Clearing explicit timing retains a metadata-only original that follows series timing and remains subject to orphan validation. Ordinary event details, previews and component-version lists suppress hidden metadata-only nodes; native busy calculations remain independent of content disclosure. Export of inherited timing still rejects rather than inventing DTSTART. Actual representable changes keep the existing independent native API/protocol-version rules; source replacements retain source versions exactly.

## Authorization and example

`readEventSource` is independent of all six ordinary event groups. Export requires it on every selected actual event, even when no metadata is present, alongside existing export/full-detail gates. All gates are rechecked after serialization. Source replacement requires it before no-op/conflict classification and again during final checks, alongside import/replacement/full-detail and applicable edit/lifecycle gates. Create-only import keeps existing import/create/lifecycle rules; it grants no read access. The trusted host receives immutable complete current/proposed metadata through existing source intents, never historical baseline payloads. Ordinary views contain no rich-source response; the authorized file is the current source-read projection.

The synthetic example file includes these properties. Its import screen explains preservation and inert links/labels; authorized export and reviewed source replacement preserve them. Native event editors do not expose metadata fields. Two-host checks cover cross-instance persistence/export and metadata-only timing/range transitions; Flutter checks inspect the exported file and preserve metadata through source replacement. CI, richer event participants/references/alarms, native metadata editors/search, scheduling, feeds and external calendar-client evidence remain separate.

[RFC property scope](rfc/rfc-5545.md), [event export](event-export.md), [source replacement](event-source-replacement.md), [selected occurrence content](event-occurrence-content.md) and [host authorization](host-authorization.md) retain their other boundaries.

[ADR 0108 participant preservation](event-source-participants.md) now adds nullable organizer/attendee claims within this same private source boundary and shared budget. It supersedes the participant-pending wording above only for the declared inert source profile.

[ADR 0109 source references](event-source-references.md) now extend this private source boundary with unresolved basic relationships and inert URI attachments. This supersedes references-pending wording only for that bounded profile; native graph/file editors and RFC 9253 extensions remain separate.

## Unarmed event source alarms, 2026-10-24

[ADR 0110](adr/0110-unarmed-event-source-alarms.md) now extends the supported source profile with [unarmed VEVENT DISPLAY alarms and bounded sibling snoozes](event-source-alarms.md). Nullable immutable server-only alarm/duration DTOs use existing metadata JSON, without table changes or a migration. Existing event-source-v2 baselines remain compatible. Separate `readEventSource` authority protects export/replacement and final/no-op checks; ordinary projections hide this data. Native edits preserve definitions and reject incompatible explicit-END anchor changes atomically. Source UID/ACKNOWLEDGED/SNOOZE are unverified data, never recipients, authority or native actions. This supersedes earlier event-alarm rejection/pending wording only for this source-preservation slice. Native personal definitions/editors, adoption, planning, delivery, feeds and client interoperability remain separate requirements.
