# Authenticated event export

Status: **implemented scoped standalone output under [ADR 0082](adr/0082-authenticated-current-event-export.md)**, following the confirmed selection/disclosure boundary in [ADR 0081](adr/0081-authenticated-event-export-contract.md). Concrete mechanics remain under draft review.

`calendarEvent.exportEvents(CalendarEventExportRequest)` returns complete authenticated standalone iCalendar bytes. The request supplies an actual `calendarId`, its expected API revision, and explicit `CalendarEventExportSelection` entries containing native event UUID and expected revision. Select complete series, not individual visible occurrences. There is no automatic all-calendar selection or redacted output. Empty, duplicate, invalid and oversized selections reject.

The service checks `CalendarPermission.exportEvents` on the actual parent and each member, plus `readEvent` with **all six supported event field groups**. Export permission alone never grants private details. The replaceable host receives immutable current content/overrides/protocol state in `CalendarEventExportIntent`, actual object/parent context and requested groups. The private imported-source snapshot is excluded. Missing/foreign/deleted objects, a wrong parent, stale revisions, denial, withheld fields or policy outage reject the whole request. Current actor/scope/policy and every source permission are checked again after serialization; no partial bytes are streamed or cached.

Output is built from current active state rather than the old import snapshot. It preserves supported DATE/UTC/exact named-zone forms, explicit end/duration/default forms, nominal duration units, recurrence/WKST/PERIOD additions/exclusions, original occurrence identities, single/future timing, representable single cancellation, text annotations, state-property presence and independent component versions/omissions. Native IDs, scope, revisions, audit timestamps and historical baseline contents are not emitted as extra fields. Protocol UIDs and protocol timestamps remain their independent values. The envelope and full-horizon VTIMEZONE definitions regenerate from pinned IANA data; original PRODID, unused zones and decorative zone source metadata are not archived or recovered.

The adapter validates the generated file using the same bounded pure profile as import, decodes its supported semantics and compares a temporary normalized **current** source value. It never compares or exports the stored historical import baseline. A mismatch rejects rather than discarding state or changing meaning. This also protects against status/presence combinations that would turn an inherited state into independent cancellation after reimport.

**Initial representability limit:** a native cancellation-only exception with no explicit replacement time follows series timing when restored. Our current wire import stores an explicit cancellation-component span. Inventing one on export would change later restoration behavior, so the maintainer selected explicit rejection of the entire series/selection until a faithful mapping is available. A cancellation with a retained explicit span remains eligible if the full round trip matches. Missing checkpoints, duplicate exact source UIDs and all other unsupported/over-limit output reject. Native state remains stored and usable; it is never silently rewritten for export.

The initial output allows at most 128 raw VEVENT components, including override components, and retains the existing per-series, syntax, explicit-date/filter, recurrence-work and full-horizon zone limits. Service output sorts exact protocol UIDs and zone identifiers, yielding deterministic bytes for unchanged current state and pins. Export is read-only: no API/protocol/audit/baseline/scope-generation change. No HTTP subscription, invitations, scheduling METHOD, network retrieval or alarm action is created.

The example exports one explicitly selected saved series, displays returned text and offers copy. It uses revision checks and rejects unsaved/unsupported state. The typed API supports multi-series selections with the same complete-or-failure rule. [Validation](scaffold-validation.md) records unit/database/two-host/Flutter evidence; external-client interoperability and clipboard behavior are separate evidence. [Timezone limits and updates](timezone-data.md) and the whole-second [1970,2100) profile remain unchanged.
