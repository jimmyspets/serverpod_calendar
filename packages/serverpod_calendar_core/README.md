# serverpod_calendar_core

Current policy: **whole-second calendar timing**, ordinary dates **1970-01-01 inclusive to 2100-01-01 exclusive**. Only explicit exclusive ends may use the midnight 2100 boundary. The timezone library remains 0.11.2; generated IANA 2026e transitions now cover the horizon with UTC boundary padding. Unknown offsets reject. See [ADR 0041](../../docs/adr/0041-whole-second-1970-2100-profile.md) and [timezone updates](../../docs/timezone-data.md). The older microsecond/2037/broad-date profile is superseded.

Framework-independent Dart calendar semantics:

- `UtcWindow`: validated UTC bounds, half-open membership and overlap/intersection. Exact BigInt elapsed microseconds; the Duration getter rejects relative lengths beyond 2^53−1 microseconds rather than rounding/wrapping.
- `UtcEventSpan`: preserved UTC end/duration/default form, exact elapsed microseconds, positive intervals and omitted-end point markers. Points can appear in queries without occupying an interval; no recurrence or booking policy.
- `CalendarDate`: Gregorian date-only fields for ordinary years 1970–2099, strict date validation, leap-year/month lengths, calendar-day addition/distance, Monday-based weekdays, chronological ordering and value equality.
- `DateEventSpan`: DATE-only event bounds with preserved optional end/duration, exclusive-end membership/overlap, positive day/week durations and a one-day default. Effective end may reach the explicit exclusive 2100 boundary; no task or UTC occupancy integration.
- `DateEventSeries`: bounded uniform-length DATE-only occurrence queries over half-open date ranges, including earlier overlapping starts. Preserves full spans and template form; no clipping, merged occurrences, moved overrides, UTC occupancy or availability decisions.
- `CivilDateTime`: validated Gregorian wall-clock fields, whole-second precision, leap-second rejection and field ordering/equality; no implicit zone or instant.
- `CalendarDuration`: signed, unit-preserving week/day/clock magnitudes and zero fractional inputs; strict structural validation and explicit date/calendar-first zoned application and exact UTC application within bounded calculation padding. Scoped DATE/UTC event constraints exist separately; remaining component constraints and interchange are pending.
- `DateRecurrenceRule`, `DateRecurrenceFrequency`, `Weekday`, `ByDayValue`: immutable DATE-only recurrence parameters with range/combination validation and canonical filter lists; no expansion.
- `IsoWeekDate.fromDate`: native ISO week-year, week and weekday fields, independent of recurrence WKST, locale and timezone. Monday-first; week 1 contains January 4. No GUI or parser.
- `DateRecurrenceGenerator`: bounded initial DATE-only start-date generation with COUNT/UNTIL, period filters and explicit limit errors. Yearly BYWEEKNO honors all WKST values and adjacent week-years; timed recurrence is provided separately below.
- `DateRecurrenceSet`: bounded DATE-only additions/exclusions, including earlier inclusions, with exclusion precedence and unchanged rule COUNT/UNTIL. Separate explicit-input, candidate, raw-rule and final-result limits; no timed/PERIOD values or overrides.
- `DateEventException` / `DateEventOccurrence`: original DATE identity independent of a complete replacement span; cancellation and structural equality. Identity is scoped to one series context.
- `DateEventExceptionSet`: immutable native single-occurrence exceptions with bounded effective-set membership validation, duplicate/EXDATE target rejection and moved/changed-length overlap queries. Separate raw exception, validation, base and final output budgets; no range/task/protocol or persistence behavior.
- `DateEventRangeChange` / `DateEventRangeSet`: native DATE-only THISANDFUTURE timing shifts and span changes, ordered by original anchors with separate singles preserved. One bounded inverse-query envelope shares recurrence budgets; no range cancellation, pattern rewrite or timed/task/wire/service behavior.
- `NamedZoneResolver`: pinned IANA names/aliases, RFC explicit gap/fold resolution, original-field preservation and explicit coverage failures, plus guarded UTC-to-local projection. Ordinary civil dates 1970–2099 plus the exclusive endpoint; unknown-offset periods remain unsupported.

- `TimedValue`: explicit UTC or exact named-zone civil identity, resolved instant/version; no floating forms. UTC/zoned ordinary dates are 1970–2099, with explicit exclusive-end factories.
- `TimedRecurrenceRule` / `TimedRecurrenceGenerator`: selected minutely-through-yearly civil recurrence, hour/minute/date/position filters, UTC UNTIL, original COUNT and bounded work/output. Generated gaps skip without COUNT; folds use first instant; explicit gap DTSTART remains.
- `TimedRecurrenceSet`: additions/exclusions and positive PERIOD spans, preserving earlier additions and original count. Reject mixed profiles and conflicting period forms.
- `TimedEventSpan` / `TimedEventSeries`: UTC/zoned spans, point markers, exact-end versus nominal-duration propagation, single cancellation/replacement and original-relative THISANDFUTURE timing. Original/actual typed identities are retained with resolved spans; shared bounded queries find moved-in/out occurrences.
- `DateEventSpan.occupiedWindowIn`: explicit chosen-zone all-day projection; empty skipped-date geometry is null. Canonical dates remain zone-free.
- `DateTaskTiming` / `TimedTaskTiming`: optional start/due or positive duration, no event defaults or booked interval; bounded start-based recurrence projections. Completion, task edits and alarms remain services.
- `ZoneRulesSnapshot` / `ZoneOffsetChange`: guarded complete finite offset evidence and equal-horizon comparison; changed data-version labels require host recalculation. An already-expanded definition is not VTIMEZONE parsing or arbitrary custom-zone acceptance.

The package has no runtime dependencies on Serverpod or Flutter. It pins pure Dart `timezone` 0.11.2 and uses generated bounded IANA 2026e data. Run `dart test` and `dart test --platform chrome` from this package. See the repository [temporal core contract and validation](../../docs/temporal-core.md). The bounded native calculation milestone is implemented under [ADR 0040](../../docs/adr/0040-bounded-temporal-core-completion.md). General all-zone/year coverage, VTIMEZONE parsing/acceptance, interchange, persistent edits/task lifecycle and calendar services remain unimplemented.
